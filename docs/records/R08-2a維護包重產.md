## 契約與工具

契約寫在 `docs/資料契約.md`「私有維護包」。工具放在 `scripts/`，不放進 `lvr_pipeline/`，因為基線快照綁定 `lvr_pipeline/` 與 `uv.lock` 的指紋；放進去會使基線無法重產。

`scripts/maintenance.py export` 複製基線的 converted 與 offline-state 快照、run 綁定、檢查點與 run report，寫出含每檔雜湊與預期輸出雜湊的 `package.json`。`rebuild` 核對維護包雜湊、快照 manifest、指紋與 `verify_full`，在 `--out` 內的快照複本上重產，逐檔比對輸出。

## 結論與限制

R08-2a 依擁有者 10-16 的選項 A 通過：在乾淨 Windows 環境，只用維護包，不使用原始 ZIP 或任何重建前產物，重產的 556 個輸出檔與基線逐檔相同。原企劃要求的「乾淨 Linux」沒有達成。

跨平台限制：Linux 上 `verify_full` 因座標距離的最後一兩位浮點差異拒絕基線快照，所以 Linux 重產尚未證明。原因是兩平台數學函式庫的捨入差異，驗證程式 `lvr_pipeline/contracts/validate.py` 要求距離完全相等。修正要改 `lvr_pipeline/`，會使基線失效，所以另立工作，等下次因其他原因重建基線時一起處理。
