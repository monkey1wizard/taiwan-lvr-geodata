## 結論與限制

### R07-1

- 完成：只搬移，不改行為。程式實作完成，合成測試通過。
- 模組分配（規劃者裁定，見企劃 R07-1 卡片）：
  - `output/monthly.py`：月檔與共用函式，含 `FORMATS`、`CATEGORIES`、`MAX_ASSET_BYTES`、`safe_path`、`write_json`、`artifact`、`zip_files`。
  - `output/yearly.py`：年度點位與錯開函式、`PointsWriter`、`GIS_CONTRACT`。
  - `output/publish.py`：維護包的 `write_maintenance` 與 `extract_*`。
  - `output/verify.py`：`verify_month`、`verify_output`、`verify_points` 等，另含唯一呼叫者在此的 `haversine_m`。
  - `output/package.py`：組裝一版成品的 `package_output`。
  - 匯入方向 monthly ← yearly ← publish ← verify ← package，無循環。
- 與原卡片的差異：卡片原寫 `package_output` 放 `yearly.py`。執行者發現 `verify_points` 需要 yearly 的點位函式、`package_output` 又呼叫 `verify_output`，會循環匯入，依規則停下回報。規劃者改為新增 `output/package.py`，這是對企劃第四節目錄的小幅增補。
- 被測試 patch 的全域值改由模組物件讀取：`verify.py` 的 `monthly.attributes`，`package.py` 的 `yearly.PointsWriter`、`yearly.GIS_CONTRACT`。
- 唯一的程式內容變動：`COUNTY_LETTERS` 路徑多一層 `.parent`，因為檔案深了一層，仍指向同一個 `config/reference/lvr_county_letters.csv`。
- 舊 `export.py`、`packaging.py` 刪除，沒有轉址檔；它們不在保留相容符號表內。
- 測試只改匯入路徑與 monkeypatch 目標。`test_gis_attributes.py` 因已有本地函式 `monthly`，模組以 `out_monthly`、`out_yearly`、`out_verify` 匯入。
- 程式指紋加入 `output/*.py`，指紋值改變屬預期。

### R07-2

- 盤點（Haiku）：七項契約的正向路徑大致已有測試；`verify_month` 的拒絕檢查完全沒有篡改測試，既有的 `test_corrupted_public_month_fails` 只觸發較早的 SHA-256 檢查。
- 實作（Sonnet）：新增 `tests/integration/test_r07_2_output_contract.py`，只加測試，未改 `lvr_pipeline/`。合成資料每類別 6 筆觀測：單一門牌、真 bbox、共用經度、共用緯度、部分定位、未定位。
- 正向：(a) 三格式 ID 順序相同；(b) 完整屬性與 parquet 欄位相同；(c) 三格式與 manifest 筆數相同；(d) 未定位觀測三格式幾何皆為 null；(e) 共用經度或緯度產生 MultiPoint，所有 Polygon 寬高大於 0，rent 沒有 Polygon；(f) 部分定位為 `partial`、已定位成員數介於 0 與總數之間；(g) 多門牌的 `total_price`、`amount_minor` 等於來源值，manifest 金額合計等於逐筆加總。
- 負向：`verify_month` 接受三個檔案路徑，測試直接對篡改後的副本呼叫，不必改 manifest 雜湊。改 ID → 格式不一致；三格式一致地改金額 → 屬性與來源不符；錯誤狀態或 null 幾何配已定位成員 → 定位狀態無效；零寬、零高或 rent 的 Polygon → bbox 無效；Point 標近似 → 只有 Polygon 可近似；多一筆 NDJSON → 多餘紀錄；GeoJSON 尾端多內容 → 頁尾錯誤。全部被拒絕。
- 發現：GeoJSON 或 NDJSON 少最後一列時，錯誤為 `JSONDecodeError("Expecting value...")`。這是 `ValueError` 的子類，仍會拒絕，但訊息不明確。對應的兩個測試只斷言 `ValueError`。改善訊息屬行為變更，不在本卡範圍，留待之後的卡片。

### R07-3

- 盤點（Haiku）：年度 ZIP 已依整個月檔分片；維護包在 F-5a 已分片並有索引與重組驗證（12 個測試）；單一月檔與年度點位 CSV 超限時報錯、不分片。缺少：每片不超上限的斷言、月檔超限測試、`verify_output` 2 GiB 檢查測試、真的走到分片集合不同分支的測試、`size_report.json` 測試。
- 裁定（規劃者）：單一月檔與點位 CSV 維持報錯、不分片。企劃 6.4 只要求必要時分片，並要求維持月／年邏輯單位；實測最大月檔只用上限的 3.9%。若日後超限，另開分片契約卡。
- 實測（`fast2-output-e`）：月檔 1,683 個，最大 83,520,125 bytes；年度 ZIP 48 個，最大 107,516,121；點位 CSV 48 個，最大 42,312,708；維護分片 2 片，最大 2,031,701,063。
- 測試（Sonnet）：見命令表。年度 ZIP 超出宣告預算的分支不是死碼，但每個成員多算 512 bytes、每檔多算 4,096 bytes 的保守預算，使真實資料實際上到不了，測試以 monkeypatch 讓 ZIP 變大來觸發，只驗證分支接線。
