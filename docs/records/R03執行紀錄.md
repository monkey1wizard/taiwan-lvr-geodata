## 結論與限制

- 完成：R03-1 相容測試已鎖定；R03-2 測試已分層；R03-3 `contracts/` 已成為套件，JSON Schema 在 `lvr_pipeline/contracts/json/`。
- 沒有觸發停止條件：兩個 `building_key_v2` 一致、測試數沒有減少、沒有循環匯入、沒有修改任何測試預期值。
- 發現限制：`contracts.schema_validator` 只接受 4 個名稱，`converted-parquet.json` 是 Arrow 結構說明而非 JSON Schema，因此相容測試只檢查它是有效 JSON，並確認 `schema_validator("converted-parquet")` 拋出 `ValueError`。R03-1 卡片寫「5 份都能經 `schema_validator` 載入」與現況不符，未改程式。
- 順帶修改（卡片未列）：`processing.py` 的指紋檔案清單、`scripts/audit_legacy.py` 的模組盤點、README、CONTRIBUTING、`docs/architecture.md` 的路徑說明。`processing.py` 的 `producer_files` 鍵因此改變，舊快照的設定雜湊本來就會因程式內容變動而不同。
- R03-4 偏離：合併後的 `SCHEMAS` 含全部資料集，但 `test_arrow_contract_descriptor_matches_published_schema` 對 `parquet_io.SCHEMAS` 逐項比對只含 P1 資料集的 `converted-parquet.json`，若改用合併字典該測試必須改動。為不改測試，`contracts/schemas.py` 另外提供 `P1_DATASETS`，`parquet_io.SCHEMAS` 暫時保留為 P1 子集（保留符號）。`parquet_io` 內「是否為 P1 資料集」改用 `P1_DATASETS` 判斷。`p2_contracts.validate_rows` 已改名 `validate_dataset_rows`，`valid_coordinate` 移到 `contracts/validate.py`。`docs/architecture.md`、`CONTRIBUTING.md` 的 `p2_contracts` 說明已更新。V-03、V-04 尚未判定，由 R03-11 依證據決定。
- R03-5 停止：卡片要求刪除 `parquet_io.py`、`snapshots.py`、`processing.py` 且不留轉址檔，但 R03-1 的 `RETAINED_SYMBOLS` 列有這三個模組（`BatchWriter`、`SCHEMAS`、`rows` 等；`SnapshotStore`；`digest`、`load_snapshot`），刪除會使相容測試失敗。需要擁有者決定：保留轉址檔，或從保留清單移除。下一步：等待決定。
