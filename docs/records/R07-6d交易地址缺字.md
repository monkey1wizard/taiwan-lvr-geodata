## 擁有者決定（2026-10-14）

- 只用 `street`、`lane`、`village`、`area` 四種欄位。
- 證據只引用本專案交易資料的列不用，目前排除新竹市 `光復路■段` 與臺中市 `■富巷`。
- 同縣市同區內比對，由大到小解析。
- `?`、`■`、`？` 視為同一佔位字元。依據是統計：交易地址完全沒有 `■` 與 `？`，不視為相同時只修好 820 列，視為相同時修好 1,045 列。

規則全文見[地址規則](../地址規則.md)「補字與文字保留」。

## 程式與文件變更

- `pin-address-source` 在描述檔加入 `char_fixes`，缺少時載入失敗，`run-full` 以 `address_source_missing_char_fixes` 拒絕。
- 新模組 `lvr_pipeline/addresses/address_fixes.py`：`load_address_char_fixes` 核對雜湊並套用欄位、證據與佔位字元規則；`apply_address_char_fixes` 補字。
- `identity.split_county_town` 是縣市、鄉鎮與其後文字的唯一解析，`building_key` 也改用它。
- `normalize` 在既有 `character-fixes.csv` 補正後套用，每次套用寫一筆 `address_char_fix` 診斷。`char_fixes_sha256` 寫入 normalize 綁定、run 綁定、converted report 與 `catalog.json`。
- CLI `normalize` 需要 `--address-dir`，`normalize` 與 `export-converted` 接受 `--address-source`。
- 文件：`docs/地址規則.md`、`docs/輸出欄位.md`、重建企劃，以及重新釘選紀錄的第二次釘選段落。

子代理自行決定、經我核對接受的事項：原字串先經 `norm` 與 `arab_to_cjk`，與交易地址的正規化一致；鄉鎮代碼不在行政區表的列不用，真實檔為 0 列；補字後地址以現行縣市名與鄉鎮名重組；診斷不使該列進入查核。
