## 起因

[V-10b 核對](V-10b核對.md)的暫存量缺量測：`verify_relations` 與 `verify_output` 的 DuckDB 溢寫寫在系統 `%TEMP%`，`addresses/pool.py` 與 `results/reconcile.py` 各有一處沒有指定溢寫目錄。擁有者 10-16 選擇改程式後全量重跑。

## 實作

- 新增 `lvr_pipeline/storage/spill.py` 的 `measured_spill(parent, prefix, interval=2.0)`：在指定位置建立目錄，背景執行緒每 2 秒取樣目錄大小，結束時再取樣一次、刪除目錄並記下峰值。另有依「建置」與「階段」兩個範圍累計峰值的記錄器。不使用 `tempfile`。
- `duckdb_config(spill)` 必須指定溢寫目錄。所有 DuckDB 連線都改用 `measured_spill`：

| 位置 | 溢寫目錄 |
| --- | --- |
| `addresses/pool.py` 探測與地址池查詢 | 階段 `build/` 內 |
| `results/reconcile.py` 狀態與暫停檢查 | 階段 `build/` 或 store 的 `spill/` 內 |
| `results/review.py` | 階段 `build/` 內 |
| `output/rows.py`、`output/verify.py` | output store 的 `build/spill-<output_id>/` 內，結束後刪除 |
| `verify_relations`，publish 時 | store 的 `spill/` 內 |
| `verify_relations`，converted 時 | 階段 `build/` 內 |
| 地址稽核 `audit-address-source` | 該命令的輸出目錄內，不在 `run-full` 路徑上 |

- `quality.json` 新增 `build_spill_peak_bytes` 與 `spill_sample_interval_seconds`。publish 時的關聯驗證在 `quality.json` 寫入後才執行，所以算進 run report 的階段峰值。
- run report 的各階段與 `resources` 新增 `spill_peak_bytes`，`resources` 另記取樣間隔。
- 這三個鍵加入 `tests/acceptance/test_run_full_determinism.py` 的排除清單。
