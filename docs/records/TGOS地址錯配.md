## 一、核心問題

**已經存在於 taiwan-address-data 的地址，不應該再變成「TGOS 匯入的新資料」。** 目前流程沒有任何一步阻止這件事。

量測結果：

| 項目 | 筆數 |
| --- | --- |
| 送出給 TGOS 的地址 | 4,871 |
| TGOS 回傳成功 | 4,428 |

另有一個比「重複」更嚴重的問題，見第三節：**門牌號不同的結果，被當成已定位寫入了候選資料。**

## 二、重複問題的證據

### 2.1 這 587 筆在離線索引裡本來就是有效資料

587 筆的 `building_key` 全部存在於離線索引 `p3-address-02887978-clean`，`validity` 都是 `valid`。離線索引共 10,624,627 列，其中 valid 9,491,547、invalid_admin 737,080、invalid_address 396,000。

也就是說，這些門牌座標早已在地址 repo。它們被送去 TGOS，是因為**交易資料裡的地址文字與地址 repo 的文字寫法不同**，離線比對沒有連起來。

### 2.2 送出的文字與地址 repo 內文字的差異（原文）

格式：送出給 TGOS 的地址，對照回傳的地址。

```
送出：連江縣南竿鄉南竿鄉介壽村1之7號
回傳：連江縣南竿鄉仁愛村1鄰1之7號        （村名也不同）

送出：宜蘭縣五結鄉台興路100號五樓
回傳：宜蘭縣五結鄉中興村14鄰臺興路100號   （台／臺、樓層、村里鄰）
```

第二組的 building_key 在離線索引裡是 `v2:{"county":"10002","door":"100","locality_road":"臺興路","town":"五結鄉"}`。送出的「台興路」與索引的「臺興路」沒有被視為同一條路。這是我對這一組的推論，沒有逐筆驗證其餘 356 筆的原因。

### 2.3 重複門牌的覆蓋方式不一致：精度

既有 `roads/` 的座標是 14 位小數，TGOS 是 6 位小數。程式比對是整列字串完全相同，所以只差小數位數的門牌也被當成「衝突」。

```
roads/09007-.csv 第1018行：連江縣南竿鄉仁愛村1鄰1之7號,09007,0900701,0900701-005,1鄰,,,,,,,1之7號,119.92980030504,26.145000981449
匯入 addresses.csv 第2行： 連江縣南竿鄉仁愛村1鄰1之7號,09007,0900701,0900701-005,1鄰,,,,,,,1之7號,119.9298,26.145001
```

587 筆中有 515 筆整列不同。差異欄位的分布：

| 差異欄位 | 筆數 |
| --- | --- |
| 只有 X、Y | 417 |
| VILLAGE、X、Y | 91 |
| VILLAGE、ROAD、SECTION、LANE、X、Y | 3 |
| SECTION、X、Y | 2 |
| ROAD、LANE、X、Y | 2 |

其餘 72 筆不在這 515 筆內。我沒有再細分它們是整列完全相同，或是該門牌在 `roads/` 內有多列。

### 2.4 既有 `roads/` 自己就有重複門牌

只統計這次 patch 會碰到的 1,803 個路名檔，其中 52 個檔案內有重複的門牌：

- 重複門牌共 211 個。
- 其中 167 個兩列完全相同。
- 其中 44 個兩列座標不同。

全部 27,176 個檔案的重複數我沒有量測。

座標不同的原文例子：

```
roads/10009-太平路.csv 第1012行：雲林縣二崙鄉港後村9鄰太平路1之50號,10009,1000911,1000911-011,9鄰,太平路,,,,,,1之50號,120.396349618932,23.8147351817072
roads/10009-太平路.csv 第1040行：雲林縣二崙鄉港後村9鄰太平路1之50號,10009,1000911,1000911-011,9鄰,太平路,,,,,,1之50號,120.396465712662,23.8153956892447

roads/10004-仁愛街.csv 第263行：新竹縣新豐鄉忠孝村12鄰仁愛街27I-,10004,1000406,1000406-014,12鄰,仁愛街,,,,,,27I-,121.145148629821,24.7149820492532
roads/10004-仁愛街.csv 第264行：新竹縣新豐鄉忠孝村12鄰仁愛街27I-,10004,1000406,1000406-014,12鄰,仁愛街,,,,,,27I-,120.993139067257,24.8752754499725
```

第二組同一個門牌的經度分別是 121.145 與 120.993，相差約 15 公里，其中一列明顯錯誤。

這會讓 `materialize_addresses.py` 在合併前檢查就失敗，錯誤訊息是 `Legacy base has duplicate FULL_ADDR: 10004-中山路.csv`。這是在暫存目錄用真實資料執行得到的結果。

### 2.5 既有資料另有明顯錯誤

這兩筆也在 587 筆內，既有經度與 TGOS 剛好差 2 度：

```
roads/09020-伯玉路.csv 第48行：金門縣金城鎮東門里27鄰伯玉路一段201號 … X=120.326327680415
匯入 addresses.csv 第13行：   金門縣金城鎮東門里27鄰伯玉路一段201號 … X=118.326328
```

金門的經度約 118 度，所以我判斷既有資料是錯的，TGOS 是對的。這是依地理常識的判斷，沒有外部查證。

## 三、更嚴重的問題：門牌號不同的結果被當成已定位

### 3.1 事實

TGOS 的模糊比對設定是「分單／雙號比對、誤差不限、僅回傳一筆」。它會把送出的地址對應到「最接近的門牌」。結果是回傳的門牌號與送出的不同。

patch 的 4,264 筆中，門牌號與送出不同的有 381 筆（約 8.9%）：

| 回傳地址是否已在 `roads/` | 筆數 |
| --- | --- |
| 已在 | 230 |
| 不在 | 151 |

判斷方式：用正規表示式取第一個「N號」或「N之M號」比較，沒有涵蓋所有地址格式，所以 381 是下限的近似值。

原文例子：

```
送出：金門縣金城鎮伯玉路一段341號3樓
回傳：金門縣金城鎮東門里27鄰伯玉路一段201號

送出：宜蘭縣礁溪鄉溫泉路64號
回傳：宜蘭縣礁溪鄉德陽村4鄰溫泉路62號

送出：宜蘭縣礁溪鄉溫泉路53號12樓之3
回傳：宜蘭縣礁溪鄉德陽村4鄰溫泉路9號

送出：宜蘭縣壯圍鄉古結路58之25號
回傳：宜蘭縣壯圍鄉古結村3鄰古結路58之22號

送出：新竹縣竹北市聯興三街236巷137號
回傳：新竹縣竹北市聯興里12鄰聯興三街236巷143號
```

### 3.2 這些結果已被寫入「已定位」

我查了匯入後的 `address_index`。送出的「金門縣金城鎮伯玉路一段341號3樓」被存成：

```
building_key = v2:{"county":"09020","door":"341","locality_road":"伯玉路一段","town":"金城鎮"}
status       = located
lng, lat     = 118.326328, 24.433878
```

這個座標其實是 TGOS 對 **201 號**回傳的座標。341 號被標成已定位，用的是 201 號的位置。

這違反了兩條既有規則：
- `AGENTS.md`：不得推斷子門牌等價（`Do not infer ... sub-door equivalence`）。
- 企劃第 5 節：「座標只表示某次觀測到的門牌位置」與「不同門牌不自動共用座標」。

### 3.3 對已驗收的 T-17 的影響

T-17 候選 `p3-115q1-tgos-001-backfill` 的 located 數 48,882 → 53,310，增加的 4,428 筆都來自 TGOS 結果。其中門牌號不同的結果也被算進去。我沒有量測它們在候選月檔裡對應多少筆交易。

我先前驗收 T-17 時，檢查的是月檔格式、筆數、雜湊與年度包一致性，沒有檢查「回傳門牌是否等於送出門牌」。**所以 T-17 的驗收結論不成立，需要重開。** 這是我的疏漏。

## 五、建議的企劃修改（待你確認，尚未修改）

**R1：新增 TGOS 結果分類步驟，放在匯入與回補之間。** 每筆成功結果歸入下列一類：

| 類別 | 條件 | 處理 |
| --- | --- | --- |
| A 新增 | 回傳門牌號等於送出門牌號，且回傳地址不在地址 repo | 成為 patch 候選 |
| B 既有 | 回傳地址已在地址 repo，門牌號相同 | 只記為別名證據，不新增 patch。座標差異另列報告 |
| C 門牌不符 | 回傳門牌號不等於送出門牌號 | 隔離。不得把座標指派給送出的門牌 |
| D 寫法不符 | 村里、路名、段別拆法與地址 repo 不同 | 人工覆核 |

**R2：送出前核對。** 候選地址送出前，先用正規化（台臺、樓層、村里）再比對一次地址 repo，減少不必要的查詢與寫法差異造成的假重複。

**R3：新增「舊基底稽核」task，放在 T-19 之前。** 量測全部 27,176 個檔案的重複門牌，產出重複清單與處理規則。

**R4：重寫第 8 節的合併規則。** 明訂座標精度正規化、衝突時誰勝出、被取代的列必須寫入報告。你已決定「TGOS 優先」，但依第三節，這條規則只適用於 R1 的 A 與 B 類。C 類不能適用，因為 C 類的座標屬於另一個門牌。

**R5：重開 T-16、T-17、T-18 的驗收。** 各加測試點：回傳門牌號必須等於送出門牌號，否則不得進入已定位。
