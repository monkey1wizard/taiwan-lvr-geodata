## 發現的問題

- `scripts/verify_release.py` 的 `--commit` 預設值與 `verify-release.yml` 的 `commit` 預設值都是第一版的 `b21217e`。第二版核對必須明確指定 `ad5a44d…`，否則會核對到第一版的資料提交。腳本沒有修改。
- 預先抓取 CSV 內容失敗時，腳本靜默略過，改由 `git cat-file` 逐檔抓取，且丟棄 git 的錯誤輸出。網路中斷時只會看到 `OSError`。

## 結論與限制

- 本機完整核對通過，GitHub 兩層也通過：GitHub 上的 release 附件與 `ad5a44d` 的 `data/output/` 逐檔等於 e17b 的輸出，`verify_output` 以 `d3d504c` 執行通過。
- GitHub 層通過，與第一版一樣兩層都有跑。GitHub 的 stream 報告記錄的 `code_commit` 是預設值 `8709337`，stream 模式不執行 `verify_output`，所以不影響結果。
- 只證明公開檔案就是第二版基線的輸出，不證明內容完整。
