## 結論與限制

R08-2a 第二版通過：乾淨 Windows 與 Linux 容器都只用維護包重產，557 檔與基線逐檔相同。Linux 相符，所以 b10 距離精度通過，R08-2b 結案。

V-10b 第二版依擁有者 10-27 決定通過。e12 第一次核對時第 5 項 not-run，因為 e02 沒有階段內的磁碟取樣，也沒有 run 目錄最大值。為補這兩項，以新 run ID `e02m-20261026` 帶取樣再跑一次全量。

e02m 的 `catalog.json` 與 GeoParquet 都與 e02 逐 byte 相同，所以量測適用於 e02。輸出 ID 不同。

磁碟餘裕低於 20% 時，有約 24.6 GB 的用量不在 run 目錄內，run 目錄刪除後仍有約 25.5 GB。擁有者 10-27 同意後唯讀掃描 home 資料夾，期間寫入的檔案共約 14.3 GB：下載資料夾 6 檔 12,386,040,943 bytes，其他應用程式約 1.9 GB。其餘約 11 GB 的來源未查到。repo 與 C 槽其他資料夾沒有期間寫入的大檔。`System Volume Information` 需要系統管理員權限，沒有查。

擁有者 10-27 決定不重跑：第 5 項以 run 目錄最大值推算，記為 pass，並註明磁碟低於 20% 是外部寫入造成。推算：開始時可用空間減 run 目錄最大值為 426,318,238,083 bytes，20.83%。限制：推算假設 run 目錄以外的用量不變，未查到來源的約 11 GB 也算作外部寫入。程式只在每個階段開始前檢查 20%。
