## 實作

- `output/catalog.py` 寫入 `catalog.json`：幣別、契約版本、門牌拆解規則版本、截止年月、各批次 ZIP 雜湊，以及每個資料檔的格式、期間、年、月、類別、筆數、大小、SHA-256 與位置。GeoPackage 另列各圖層筆數。
- `output/verify.py` 的 `verify_output` 收集全部失敗後才中止，檢查項目為：目錄與檔案雜湊、欄名欄序與型別、格式中繼資料、主鍵、四種格式逐值一致、同一交易非門牌欄位一致、月份歸屬、單檔 100 MiB 上限與 50 MiB 警示，以及空值金額、單價、面積、日期的品質計數。
- `run-full` 輸出階段在提交前執行目錄與驗證。驗證失敗時寫 `verify_report.json`，不提交該階段。成功時 `output.json` 與 run report 記錄 `catalog_sha256`、警示與品質計數。
- `.gitignore` 由 `/data/` 改為 `data/*` 加 `!data/output/`。

## 結論與限制

- 合成輸出可完整驗證，篡改案例都能被指出檢查名稱與位置。
- 限制一：GeoParquet 的排序未檢查。寫入端以批次、檔名、列號數值排序，契約已改寫為同樣的規則。
- 限制二：記憶體用量只在合成資料上驗證。格式間比對一次持有一年的列摘要集合，真實資料的資源用量待 R07-10 量測。
- 限制三：`data/output/` 下的任何檔案都會被 Git 追蹤。只有經發布流程核准的輸出才能放進該目錄。
- 限制四：`NOTICE.json` 尚未產生，`config/sources/notice.json` 不存在。
