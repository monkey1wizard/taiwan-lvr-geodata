## 地址來源副本

`C:/Code/taiwan-address-data` 有他人未提交的文件修改，`pin-address-source` 拒絕非乾淨工作區。擁有者 2026-10-13 選定以本機 clone 釘選。

1. `git clone` 到 `data/cache/taiwan-address-data`，該位置受 `.gitignore` 的 `data/*` 忽略。
2. 一般 clone 無法在 Windows 建立 69 個檔名含 `?` 的 `roads/` 檔。原工作區把這 69 個檔設為 skip-worktree，所以原工作區磁碟上也沒有這些檔。副本依原工作區的 `core.protectntfs false`、`core.longpaths true` 設定，套用同一份 69 檔 skip-worktree 清單後檢出。
3. 原工作區的換行混用：`area_*.csv`、`address.html`、`address.js`、`selection.txt` 是 CRLF，`scripts/`、`supplements/`、`tests/` 與 `.github/` 等是 LF，git 內容都是 LF。全域 `core.autocrlf true` 的 clone 只把部分檔案檢出為 CRLF，第一次比對有 14 個檔位元不同。改用 `core.autocrlf false` 後換成另外 8 個檔不同。
4. 最後保留 `core.autocrlf true`，把 24 個非 `roads/`、非 `docs/`、非根目錄 `README.md` 的追蹤檔，以原工作區的位元組覆蓋到副本，再以 `git add -u` 更新副本索引。暫存差異為 0，代表 git 內容未變。副本 HEAD 為 `7cf0f3db…`，`git status --porcelain` 為 0 行，`roads/` 磁碟檔數 27176，與原工作區相同。
5. 副本與原工作區逐檔 SHA-256 比對 27200 個檔，差異 0、缺檔 0。

這 69 條路名檔在本次及前次釘選都不在 `roads` 清單內。這是既有狀態，不是本卡造成的差異。

第一次釘選（`scanned_at` 12:14:18）用的是換行未對齊的副本，其中 `README.md` 與 `scripts/update_addresses.py` 雜湊與原工作區不同。該結果已由第二次釘選（12:45:55）取代，不提交。
