## 結論與限制

### R08-1

- 提交一（只搬移）：`distribution.py` 全部移入 `output/publish.py`，舊檔刪除、無轉址檔。為避免 publish 與 verify 互相匯入，維護包的 `extract_zip`、`extract_indexed_handoff`、`extract_handoff` 移到 `output/verify.py`，`write_maintenance` 留在 publish。匯入方向 monthly ← yearly ← verify ← publish ← package。沒有測試以舊模組名 patch，所以不需改 monkeypatch 目標。
- 提交二：`scripts/verify_public_snapshot.py` 的流程改為 `output/package.py` 的 `verify_public_snapshot()`，新增子命令 `verify-public-snapshot`（選項與舊腳本相同），`verify-public-output.yml` 改呼叫新子命令，舊腳本刪除，CONTRIBUTING.md 更新。子命令數 28 改 29，是卡片預期的變更。
- 與卡片的差異：卡片寫併入 `publish.py`。新函式要呼叫 `package_output`，而 package 已匯入 publish，放在 publish 會循環，所以規劃者改放 `package.py`。
- 新測試 `tests/integration/test_r08_1_public_snapshot.py`：以合成成品與本機傳輸，確認可重產全部月檔且結果為 pass；把公開 manifest 的月檔雜湊改掉時丟出「Cloud rebuilt monthly bytes differ from public snapshot」。
- 發現：沿用的流程把 `unmatched_selection_verified` 寫死為 true，沒有實際驗證「維護包能產生全歷史未定位候選」。V-11 要求這一項，留給 R08-2 補上實際檢查。
- 限制：`verify-public-output.yml` 只能手動觸發，這次推送沒有實際跑過公開快照重產。

### R08-2

- 實作（Sonnet）：workflow 改名為 `verify-release.yml`。`tgos/batches.py` 抽出 `select_unmatched_candidates()`，`prepare_tgos` 改呼叫它，迴圈本體逐字搬移，既有 TGOS 測試不變而通過。`output/package.py` 新增 `verify_unmatched_candidates(state)`，不讀送查紀錄、不算配額，只算全歷史候選數。
- 等式：候選數 + 暫停縣市排除數 = 狀態 `status_counts` 的 unmatched + outside_scope。不符時丟出 `Unmatched candidate selection differs from state status_counts`。
- 真實資料核對（規劃者）：R07-4 狀態候選 185,639，差額 3,167 與 R09-0 量到的澎湖、金門暫停縣市未命中鍵（1,449 + 1,718）相同。
- 手動觸發失敗的原因：舊公開版本的轉換快照沒有記錄正規化版本。現行程式驗證元件時以 v2.5 規則重算地址鍵（`contracts/validate.py`），與舊鍵不同而拒絕。R03-12b 已記錄：沒有版本的快照會照舊重算，規則升版後會失敗。這是已知限制，不放寬檢查；舊公開版本仍可下載，但無法以現行程式重產驗證。
- 待完成：R07-4 候選公開後（R08-3，需擁有者同意），對它觸發 `verify-release`，作為 R08-2 完成條件與 V-11 證據。
