## 結論與限制

V-13 以第二次 run `v13-20261018b` 判定為 pass。本驗收只證明回補機制在真實資料上正確，不代表任何擁有者判定，也沒有發布。

第一次 run 找到兩個問題：

1. **輸出漏掉地址池改名的門牌。** 輸出與 `final-state` 用地址成員原本的鍵對應定位結果，但地址池會把部分鍵改為現行鄉鎮名，例如頭份鎮改為頭份市、員林鎮改為員林市。這些門牌已定位，卻沒有寫進輸出。已發布的第一版因此少了 380,134 個已定位門牌：依成員原鍵為 3,551,724 列，依地址出現列的鍵為 3,931,858 列。已在 `7d969c2` 修正，第二次 run 的輸出為 3,943,412 列。第一版要不要另行更正，由擁有者決定，已記入總表的已知風險。
2. **凍結複本記錄的程式版本會錯。** 用 `git archive` 匯出的凍結複本沒有 `.git`，run 綁定的 `code_commit` 會取主 repo 當下的 HEAD。第一次 run 的程式是 `70fe754`，記錄卻是 `4f6b276`；主 repo 再有新提交後，同一 run 就無法重跑。已轉告B 段，記在 00 主企劃的 e00。第二次改用 `--shared` 複本，記錄正確。

另有一個標示問題：`affected_months.json` 的 `baseline_run_id` 記成比較基準的快照 ID `final-state-5503805b22e269131c3a0372`，不是 run ID。它不影響核對結果，留給後續修正。
