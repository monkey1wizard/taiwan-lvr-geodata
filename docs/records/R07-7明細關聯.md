## 設計

- `ingest` 讀入與主檔同一 ZIP 的 `{縣市字母}_lvr_land_{類別字母}_{build|land|park}.csv`，寫入新資料集 `ingest-detail`。每列以 `observation_id(ZIP 雜湊, 明細成員路徑, 實體行號)` 作 `detail_record_id`。讀取器、空白列與重複標題處理與主檔相同。
- 明細檔第二行只在「欄數等於標題，且每個值都是不含數字的非空 ASCII 標籤」時視為英文標題列並略過，略過的內容存入報告的 `english_label`。真實明細列含中文或數字，不會被略過。
- `normalize` 在每個檔案組內，以去除首尾空白後的 `編號` 建立主檔對照，只用 `row_status` 為 `parsed` 的主檔列，包含被排除的列。連結結果寫入新資料集 `detail`，以 `raw_record_id` 對應主檔。
- 七項計數寫入報告的 `detail_link`，按批次、縣市字母、類別與明細種類分列。`run-full` 的 run report 帶出 `detail_link` 與 `rows.detail_rows`。
- `load_snapshot` 核對 `ingest-detail` 與 `detail` 的列數。`verify_relations` 要求 `detail.raw_record_id` 存在於 `disposition`。

## 結論與限制

- 程式完成，合成驗收通過。
- 修正子代理實作的一個風險：原規則會把第二行中 `編號` 為純文字的真實明細列誤當英文標題而略過。已改為只略過全為 ASCII 標籤的列，並保留被略過的內容供追查。
- 子代理的實作選擇已採用：英文列需與標題同欄數；明細標題有重複或空欄名時與主檔一樣中止；主檔不存在但明細存在時，明細列計入 `detail_unmatched`；每個檔案組三種明細都列出計數，不適用者為 0。
- 限制：預售屋沒有 `_build.csv` 時，每個預售屋檔案組都會計一次 `detail_member_missing`。這是契約「不把缺檔視為沒有明細」的直接結果。
