# 內部資料契約

本文件說明來源觀測、地址成員、地址鍵、定位證據、狀態及快照間的內部關聯。它不定義公開欄位。公開輸出規格唯一見[輸出欄位](輸出欄位.md)。階段輸入與產物見[資料處理流程](資料處理流程.md)。

## 2026-10-12 重建與信任邊界

本次決定中的「既有」與「舊結果」指全新重建開始前已存在的處理產物。本次重建完成獨立驗收後，新產生的維護包及結果可依企劃供 R08 候選重產與 R10 回補使用，不能藉此納入重建前的產物。

既有衍生結果全部不可信，不作新流程輸入、定位依據或新版驗收基準。範圍包括 normalized／converted、地址池／index／state、aliases、TGOS 採用結果、review 裁定、衍生 cache、快照、維護包、公開輸出及統計。歷史 raw ZIP、地址來源與 TGOS 原始回傳保留追查，但不能因曾輸入舊流程或通過舊驗收而視為已核驗或自動沿用。新 run 須重建來源清冊並重新核對原文和來源涵蓋。TGOS 舊回傳預設不納入，須先有新規則核對送出地址與回傳原文同址，再明確判定採用資格。

送查帳本及已送出紀錄不可清空或繞過，避免重複送查；帳本只表達送出狀態，不繼承任何舊定位。新 run 的快照限於本次重建中已依新規則驗證、且輸入綁定相同的階段。隔離護欄已於 2026-10-12 實作（R07-6a）：沒有 `rebuild_epoch = 2026-10-12` 的快照與 run 一律拒絕讀入，規則版本不符的快照也拒絕；`run-full` 只接受帶本次紀元且 `source_check.status` 為 `verified` 的來源清冊與地址來源描述。舊公開輸出目錄、維護包及 TGOS `--ledger` 轉接不在此護欄範圍，分別由 R07-8 與 R09-2 處理。

## 資料單位與關聯

```text
來源檔案列
  └── 來源觀測 raw_record_id
        └── 一個或多個地址成員 component_id
              └── 地址鍵 building_key
                    └── 零個或多個定位證據
                          └── 定位狀態與採用結果
```

| 單位 | 識別及含義 | 關聯原則 |
| --- | --- | --- |
| 交易 | 原始來源主檔一列 | 不跨批次合併，不依相同地址或原始流水號推斷多列相同 |
| 來源觀測 | `raw_record_id` 由來源 ZIP 雜湊、ZIP 內成員路徑及實體列號識別主檔列 | 保留每個來源列及其去向。不推斷修訂先後 |
| 地址成員 | `component_id` 由來源觀測及地址拆解序號識別一個門牌成員，內部序號從 0 起 | 一筆觀測可有多個成員。地址欄原文及拆解順序要保留 |
| 地址鍵 | 目標介面 `building_key` 依現行 v2 地址規則識別門牌；規則版本放入 metadata | 多個觀測成員可指向同鍵。只共用本次重建定位結果，不合併觀測 |
| 定位證據 | `evidence_id` 及來源參照指向一筆地址或座標依據 | 保留候選、來源、輸入版本、座標與採用或拒絕原因 |
| 定位狀態 | 以地址鍵表示目前可用的定位結論 | `located`、`unmatched`、`conflict` 及 `outside_scope` 是不同結果，不可互換 |

公開 `transaction_id` 於 2026-10-12 由 R07-6 定案為可讀自然鍵 `{src_batch}/{member_path}/{source_row_number}`。它與內部 `raw_record_id` 由相同三項輸入算出，一對一對應。批次 ZIP 的 SHA-256 記在 `catalog.json`，id 加批次雜湊才是完整來源身分。公開主鍵是 `transaction_id` 加 `door_index`，不另設 `door_id`。公開 `door_index` 從 1 起算，等於內部 `component_id` 的 0 起算序號加 1。完整規則見[輸出欄位](輸出欄位.md)的識別契約。

## 來源觀測及去向

交易主檔一列是來源觀測。正規化後，每列有且只有一個主要去向：保留、排除或解析失敗。排除原因及解析錯誤屬診斷資訊，不替代主要去向。每個來源 ZIP 成員的輸入列數必須等於三種去向總和。

內部金額 `amount_minor` 以新臺幣分儲存，比例為 100。同一來源觀測的金額不可因拆成多個地址成員而重複計算。面積以平方公尺十進位文字保留；數值 `0` 與缺值 `null` 必須區別。這些是內部契約，不能與公開欄位的整數元及 double 面積型別混為一談。

類別由來源檔名標記：`sales` 為買賣、`presale` 為預售屋、`rent` 為租賃。批次季別不等於交易年月。日期須由 `validated_roc_to_tx_yyyymm` 驗證並轉換，不能直接截取字串推定。常見排除原因包括土地、無門牌地址、純車位及無效日期，各自保留原因。來源描述標為空批次時須有證據，檔案缺失不可視為空資料。

目前讀取端只讀主檔。建物 `_build.csv`、土地 `_land.csv`、車位 `_park.csv` 是分列明細，程式尚未讀入。關聯鍵、檔案組範圍與六種例外的處理於 2026-10-12 由 R07-6 定案，見[輸出欄位](輸出欄位.md)的明細關聯契約。明細只在同一 ZIP、同一縣市字母、同一類別的檔案組內以 `編號` 關聯。`編號` 是否存在且唯一由建置時逐檔檢查判定並寫入 run report，不先假設。不可僅依主檔地址文字或相同編號推斷跨來源交易相同。

## 地址成員與門牌鍵

地址成員保留來源觀測識別、地址欄原文、拆解結果、順序及規則版本。無法拆出完整門牌的成員仍留在診斷與待查核資料，不從觀測關聯中刪除。

`building_key` 是唯一目標門牌鍵名稱，用於跨觀測關聯本次重建中的同一門牌定位結果。鍵內容與正規化細節以[地址規則](地址規則.md)為準。`building_key_v2` 函式與 `legacy_building_key` 欄位已於 2026-10-12 移除，不得重新加入 alias、wrapper、雙軌或舊結果 fallback。樓層不是門牌鍵的一部分。未證明身分相同的主號、子號、村里、鄰或門牌文字變體不得合併。

地址鍵不是來源觀測 ID、明細列 ID 或公開交易 ID。地址鍵重用不允許去重觀測，也不代表來源有完整歷史涵蓋。

## 定位證據與狀態

定位決策以地址鍵為單位，觀測到地址成員的關聯保留原樣。證據至少須能追溯來源版本、原始識別、地址比較結果、候選座標及規則版本。沒有被採用的候選也要保留拒絕原因。座標需明確坐標參考系及軸向，軸向未確認時不得採用。

| 狀態 | 用途 |
| --- | --- |
| `located` | 有通過同址與座標驗證的可用座標 |
| `unmatched` | 固定地址來源中沒有符合候選 |
| `conflict` | 候選身分或座標相互矛盾，未採用定位 |
| `outside_scope` | 來源地址或查詢不在本輪固定範圍。澎湖及金門暫停定位使用 `conflict` 加 `address_source_suspended`，不能記為 `outside_scope` |

同一來源地址的不同座標、同一門牌多筆候選及多門牌歧義必須分開處理。30 m 容許值只適用於同一已確認門牌內的座標差異。定位證據不證明歷史建物在所有交易時間都位於同一位置。

TGOS 帳本保存查詢原文、批次、回傳雜湊、送出狀態及匯入結果。相同批次和相同回傳雜湊重匯具冪等性。查詢與回傳需集合一對一。`submission_unknown` 保留原狀態，不能自動釋放名額或重新送出。

批次送出生命週期狀態包括 `prepared`、`submitted`、`submission_unknown`、`cancelled`。回傳匯入後狀態為 `completed`。查無或拒絕是回傳列結果，不是可替代批次送出狀態的值。每個交換檔最多 10,000 筆，這是單檔上限，不是每日程式限制。`data/tgos/date.json` 的日期只決定交換資料夾名稱，不參與候選、批次識別、送出狀態或匯入判定。

地址補充 CSV 的 14 欄名稱、順序及映射唯一見[地址規則](地址規則.md)。內部資料須保留來源關聯、採用依據及隔離原因。產生候選不代表地址專案已匯入。

## 快照、版本及續跑

每次新 run 固定本次獨立重核的來源清單、原始輸入雜湊、地址來源、地址規則版本 metadata、程式版本、契約版本及截止年月。不得使用過去 run 的衍生快照；只可在本次新 run 內重用已驗證且輸入綁定一致的階段。綁定改變時建立新結果，不覆寫原始證據。

目前 `run-full` 已具來源核對、階段快照、續跑、離線處理及 run report。R07-6a 護欄要求快照綁定與 run 綁定都含 `rebuild_epoch`，並在寫入前檢查來源清冊的 `source_check`。程式尚未將 TGOS 狀態接入 `run-full`。各 CLI 命令與預設工作路徑仍可能使用 `data/work/`。新版目標布局中 TGOS 狀態移入 run 目錄，需相關工作實作及驗收後才生效。

執行或階段驗證失敗時，保留失敗狀態與必要診斷在 `data/tmp/<purpose>/`。失敗或尚未完成的快照不進入可重用階段清單。公開輸出目錄契約見[輸出欄位](輸出欄位.md)。
