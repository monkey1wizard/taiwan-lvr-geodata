# 00 主企劃：全歷史實價登錄門牌座標重建

修訂日期：2026-10-18，Asia/Taipei。這份文件講整個專案的大架構、三個里程碑、現在走到哪、誰手上有事，以及 A 到 G 七段工作的全部任務。任務編號是段落字母加兩位數，例如 `a01`、`b02`。工作量大到要拆出去的段落另有子企劃檔，目前只有 B 與 D。規則的權威內容在[地址規則](../地址規則.md)、[資料契約](../資料契約.md)、[輸出欄位](../輸出欄位.md)。所有有效擁有者決定、驗收狀態與證據索引在[擁有者決定與驗收總表](擁有者決定與驗收總表.md)。

## 一、目標

把內政部實價登錄從 2011 年至今的每一筆交易門牌配上經緯度，公開成每月每類別的 CSV 與一個 GeoParquet 檔。配座標有兩條路：先用固定版本的地址資料庫離線配對，配不到的再送內政部 TGOS 門牌定位服務查，TGOS 也查不到的交給擁有者逐筆判定。

## 二、系統架構

### 資料怎麼流

```text
58 個原始 ZIP ─┐
               ├─ run-full ─ 讀入 → 正規化 → 轉換 → 地址池 → 離線索引 → 離線定位
釘選地址來源 ──┘                                                   │
                                                 ┌─ TGOS 狀態 ←─ 帳本  │
                                                 ↓                     ↓
TGOS 每日交換 ──→ 帳本                        待查核表 ←──── 離線定位結果
                                                 │                     │
擁有者判定檔 ──→ 第二類人工查核區 ──→ 回補 ──→ 受影響月份重建 ──→ 輸出
                                                                       ├─ data/output/ 每月 CSV
                                                                       └─ GitHub release GeoParquet
```

「TGOS 狀態」這一格尚未接進 `run-full`，由 B 段實作。

### 四個速度不同的迴圈

| 迴圈 | 速度 | 性質 | 跨迴圈留下什麼 |
| --- | --- | --- | --- |
| 離線流程 `run-full` | 約 2 小時 | 確定性。規則或程式改一個字就要整個重跑，產生一個新 run | run 目錄與輸出。通過驗收的那個 run 叫基線 |
| TGOS 交換 | 每天一批，不可逆 | 外部服務。送出的查詢文字與回傳都是證據 | 帳本：查詢原文、批次、回傳原文、雜湊。每次新 run 以當時規則重新解讀同一份回傳 |
| 人工判定 | 以週計 | 擁有者逐筆判定 TGOS 後仍無座標的門牌 | 判定檔，跨 run 沿用 |
| 發布 | 以版本計 | 某個 run 的輸出快照 | 第一版、第二版。晚到的回傳與判定經回補成為增量更新 |

### 三條原則

1. **規則定稿在前，配額在後。** 查詢文字由規則產生。規則改了，已產生未送出的批次作廢要重產，已送出的永久留在帳本。所以會改門牌鍵或查詢文字的修正，都要在送出前做完。
2. **TGOS 回傳是不可變證據，解讀隨規則版本。** 採用與否在每次 run 重新判定。規則改了不必重送。
3. **輸出按 run 版本化，晚到的證據走回補，不走重送。** 第二版之後每一批回傳、每一筆判定都是增量。

### 名詞

| 名詞 | 意思 |
| --- | --- |
| 基線 | 通過驗收、作為後續工作起點的那一次全量 run。目前是 `r07-10-20261016b` |
| 帳本 | TGOS 查詢與回傳的完整紀錄，防止重送，並在每次 run 重新解讀回傳 |
| 門牌鍵 | 一個門牌的身分：縣市、區、街路、門牌號，加上地址有寫的村里與鄰 |
| 第一版 | 只含離線配對座標的公開資料。CSV 已在 GitHub |
| 第二版 | 加上 TGOS 回補座標的公開資料 |
| 第二類人工查核區 | TGOS 也查不到的門牌，等擁有者逐筆判定的集合 |

### 為什麼現在不送第 2 批

第 1 批結果暴露三個問題。送出的地址帶樓層，TGOS 幾乎查不到，這個已修並重產過一次。我們自己的地址解析有缺陷，例如「瑞穗鄉瑞穗鄉」重複、「七之1號」拆錯、村里欄混進鄉名，這些地址送出去是白送，還沒修。交易地址寫的村里、鄰常是舊的，TGOS 回現行名稱，現行比對規則把它們當不同門牌拒絕，規則已決定，程式沒改。每送一批花掉一天且不能收回，所以先修好、重跑、重產送查檔，再每天送。延後約 3 天開始，換 12 天配額都花在正確的查詢上。

### 接下來三段

1. **修好再送，約 3 天。** B 段。改程式、重跑全量產生新基線、重做送查檔。期間不送 TGOS。
2. **邊送邊補，約 12 天。** C 段與 D 段同時進行。擁有者每天送一批，程式當天匯入；同時把人工查核區與回補機制做出來。
3. **第二版與持續更新。** E 段起。發第二版，之後每輪 TGOS 與每筆判定都用回補補進公開檔案。

## 七、工作方式

- 在 `main` 修改、本地驗收、本機提交。不推送、不建分支或 PR。

- `data/runs/` 下的基線與 TGOS run 目錄只讀。檢查產物放 `data/tmp/<purpose>/`。
- 正式文件不超過 550 行。舊企劃原文在 git 歷史，提交 `c3f1284` 之前。
