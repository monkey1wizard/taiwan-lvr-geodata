## R09-2 完整同址核對

**規則 A：回傳逐項核對。** 保留 `same_door` 的簽章核對：縣市、行政區、街路與段、巷弄、主號、子號。補上沒有對應碼的拒絕：座標只有一半、非數字座標記 `tgos_coordinate_invalid`；成功列缺 `Response_Address` 記 `tgos_response_incomplete`。每個拒絕原因都要對應到待查核碼，不留裸字串。

**規則 B：跨村里或鄰歧義。** 對查詢鍵沒寫村里的層級，取本次 run 地址池 `address-result` 中與查詢鍵門牌簽章相同、且符合查詢已寫層級的其他鍵。這些鍵若寫出兩個以上不同的村里，回傳不採用，記 `tgos_village_ambiguous`。鄰以同樣方式另外判定：只看村里與查詢相容的鍵，鄰有兩個以上不同值時同樣記 `tgos_village_ambiguous`。只有零或一個值時，照 `same_door` 判定。歧義檢查在 `same_door` 通過後、採用座標前執行。新碼加入 `EXCEPTION_REASON_CODES` 與 `TGOS_REJECTION_CODES`。

**規則 C：CRS 與軸向。** 回傳只有 `Response_X`、`Response_Y`，契約定為 WGS84 經度、緯度。不新增欄位推斷。以案例證明：經緯對調、TWD97 公尺座標都被範圍檢查拒絕為 `tgos_coordinate_invalid`。

**帳本帶入整理。** 依決定 6 保留 `--ledger` 與 `_carry_ledger`。刪除 `UNCARRIED`、`UNCARRIED_REASON`、`tgos_uncarried_queries`、`tgos_query_unkeyed` 及其在 `review.py`、`storage/parquet.py`、`storage/runs.py`、`tgos/validate.py`、`tgos/__init__.py`、`schemas.py` 的處理。同紀元帳本中若有查詢在現行規則下算不出門牌鍵，`prepare-tgos` 直接拒絕，不另列清單。R09-6 的缺區查詢依 R09-6 的身分規則帶入，不算無鍵。

**路徑。** TGOS 命令與 `build-review` 改為必填 `--run-id`，`--work-dir` 移除，狀態寫入 `data/runs/<run-id>/tgos-state/`。`--exchange-dir` 預設維持 `data/tgos`。`data/runs/<run-id>/manifest.json` 已存在時拒絕，避免寫進 `run-full` 的 run 目錄。

**測試。** 依來源規格建立新案例：`341／201`、`64／62`、`58之25／58之22` 不同號、同號不同路、回傳缺列、回傳多列、跨村里候選兩值拒絕、單值接受、鄰歧義、經緯對調、TWD97 座標、半個座標。刪除 `tests/integration/test_r09_0_tgos_rebuild.py` 中只測無鍵帶入的案例；`test_r05_9_suspension.py` 的 `_with_earlier_kinmen_query` 若依賴無鍵帶入，改用正確夾具。R09-1 紀錄指出 `test_same_address_text_already_sent_is_not_selected_again` 強度不足，改為能因改錯目標而失敗。

**驗收。** 上列案例全部通過；`grep` 確認 `UNCARRIED`、`tgos_query_unkeyed` 只剩歷史紀錄；全套 pytest 通過。

## R09-3 冪等與 `submission_unknown`

- completed 批次以相同回傳雜湊重匯：快照 ID 不變、不寫新快照。已有測試則補斷言快照目錄數不變。
- completed 批次以不同回傳雜湊重匯：拒絕，錯誤訊息寫出兩個雜湊，不寫新快照。
- `submission_unknown` 批次：不被重選；`--retry-query-fingerprint` 指定它時拒絕；匯入回傳可接受並改為 completed；改為 cancelled 後才可重送。
- 驗收：上列案例各有測試，重匯後證據列數與結果列數不變；全套 pytest 通過。

## R09-6 缺區地址送查

**送查集合。** 有縣市、`reason = district_missing` 的地址池出現列，依 `normalized_address` 去重。送查前以離線索引找出該縣市中有相同街路與段的行政區，作為候選區；沒有任何候選區的地址不送，記入報告計數。

**查詢身分。** 缺區查詢沒有門牌鍵。`tgos-query` 的 `building_key` 允許為空，只限 `query_kind = district_missing`；`query_fingerprint` 為 `digest(["district_missing", county_code, normalized_address])`。同一地址文字不得重送的規則照舊適用。帳本帶入時這類查詢依同一公式核對，不算無鍵。

**採用規則。** 回傳須通過規則 A 與規則 C；回傳的縣市等於查詢縣市；回傳行政區屬於候選區；回傳去掉行政區、村里、鄰後的街路、巷弄、主號與子號等於查詢；查詢寫的村里或鄰不得不同。通過時結果記錄回傳的門牌鍵與座標，`reason = tgos_district_fill`。不通過記對應拒絕碼。

**進入輸出。** R09-6 只做送查與匯入。採用結果在 R09-8 的地址池建置時補區：該出現列以 TGOS 回傳的門牌鍵入池，原交易地址不改。

**驗收。** 合成案例：候選區內接受、候選區外拒絕、無候選不送、號不同拒絕、村里不同拒絕、帳本帶入身分不變。全套 pytest 通過。

## 陷阱

- 不得在 R09-8 之前改距離精度，理由見「卡片順序」。
- 不得刪除 tgos-state 的中間快照，除非已證明最新快照的 `expected_parent` 鏈不需要它們。
- `prepare-tgos` 讀基線 offline-state 只核對內部一致與紀元，不核對程式指紋；這是允許的，因為帳本之後會在 R09-9 以新程式重新匯入。
- `data/tgos/` 的送查檔與回傳是擁有者交換證據，不覆寫、不刪除。
- 合成測試若因新檢查失敗，改用正確夾具，不加繞過旗標。
