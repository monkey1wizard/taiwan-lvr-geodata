## 陷阱

- 本子企劃期間不得上傳現有第 2 批。
- 不得在 B-5 之前單獨改距離精度：TGOS 命令複製基線 `coordinate-resolution` 時逐列重驗，先改精度會使讀基線失敗。B-2 與 B-5 一起進全量重跑。
- `prepare-tgos` 讀基線 offline-state 只核對內部一致與紀元，不核對程式指紋；這是允許的，因為帳本之後會以新程式重新匯入。
- `data/tgos/` 的送查檔與回傳是擁有者交換證據，不覆寫、不刪除。
- 不得刪除 tgos-state 的中間快照，除非已證明最新快照的 `expected_parent` 鏈不需要它們。
- 判定只決定採用與否，不改 `building_key`、不合併門牌鍵。
- 合成測試若因新檢查失敗，改用正確夾具，不加繞過旗標。
- 三個 session 曾共用這個 checkout。提交只用 `git add <明確路徑>`，改 00 或 08 前先 `git diff` 確認乾淨。
