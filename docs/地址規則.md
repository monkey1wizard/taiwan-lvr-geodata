# 地址處理規則

本文件是補字、拆解、地址身分、離線定位、座標採用及 TGOS 同址規則的唯一權威來源。規則已決定或舊版測試通過，不代表所有新版流程已實作或驗收。現行 v2 規則只作為獨立重驗起點；案例若證明規則有誤，須修訂規則及預期，不得為相容舊結果而保留錯誤。證據與工作狀態見[重建企劃](plans/重建企劃.md)及對應 R records。

2026-10-12 決定只保留 `building_key` 作為門牌鍵名稱，以重新驗證後的現行 v2 規則取代舊 `building_key` 演算法，並將規則版本寫入 metadata。現行程式仍有 `building_key_v2` 函式，遷移尚未實作。R07-6b 必須移除該函式、匯出及呼叫，也必須移除 `legacy_building_key` 欄位及所有讀寫和依賴；不得保留 alias、wrapper、雙軌或舊結果 fallback。依賴盤點是移除前的實作步驟，不是例外。本文件所載規則和既有測試只作獨立重驗起點；發現錯誤時須修訂規則與預期，不得為相容舊結果而保留錯誤。既有定位及衍生結果不沿用。

## 補字與文字保留

保留來源地址原文、正規化文字、修正後文字、套用規則、規則版本及依據。補字規則必須有適用範圍。問號不得作為無條件的全域替換。

缺字候選只有在文字解唯一且有有效門牌證據時才可採用。多解、無解或證據不足時保留原字、候選與診斷，交由查核。不可先刪除來源字元再建立已定位地址。R-04 的 V-05、V-06 pass 僅保留為歷史紀錄，本輪須以獨立案例重新驗收。

## `building_key` 完整身分

現行程式函式 `building_key_v2` 使用 `v2:` 前綴及 `key_version = "v2"`，`NORMALIZATION_VERSION` 為 `v2.5`，並納入 normalize、address-pool 與 offline-index 綁定。這些是現況，尚非遷移完成。R07-6b 須將函式、匯出與呼叫統一為 `building_key`，將規則版本記於 metadata，並移除 `legacy_building_key` 欄位及所有讀寫與依賴。不得以 alias、wrapper、雙軌或舊結果 fallback 保留舊名稱。現行 v2 鍵規則為排序後的 JSON，含六欄，供獨立重驗起步：

| 欄位 | 意義 |
| --- | --- |
| `county` | 縣市代碼 |
| `town` | 鄉鎮市區名。以「里」結尾的鄉名也可解析 |
| `locality_road` | 街路與段，或地名，再加巷、弄、衖、衕、文字巷名或街路後接地名。只有村里時為空字串 |
| `door` | 臨、建、特及號，含之號與附號。寫法保留，例如 `10`、`10之1`、`10號之1`、`30附1`、`6號附9`、`臨201` |
| `village` | 地址全文寫出的村里，位於區名之後、街路之前。未寫時不出現 |
| `neighborhood` | 地址全文寫出的鄰，轉為阿拉伯數字。`006鄰` 與 `六鄰` 都表示 `6`，未寫時不出現 |

前四欄形成門牌簽章 `door signature`，村里和鄰是子識別 `subid`。兩筆地址只差村里或鄰時仍是不同門牌。村里依地址原文，不讀地址資料的 `VILLAGE` 代碼。地址鍵只識別門牌，不識別或合併交易觀測。

### 字元與排除規則

- 國字主號轉為阿拉伯數字，全形英文字母轉半形。
- 樓、樓之、樓後接數字、室、地下室、地下層、地下 N 樓或層、底層及括號註記不參與門牌辨識。
- 路名中的「至」「及」「與」只有在前一字為數字或地址單位時才視為區間符號。
- `N之M` 與 `N號之M`、附號寫在號前或號後、文字巷名有無、巷弄數字用國字或阿拉伯數字，不自動視為相同。資料中出現配對時列入待查核。
- 村里異體字或改名不自行映射。新竹縣地址資料中的 `I-`、`G-`、`H-` 編碼仍可能無法建立鍵。缺乏證據的舊門牌與現行門牌不連結。

### 重複縣市名

現行 `canonicalize` 與 `building_key_v2` 共用 `identity.drop_repeated_county`，只刪除完全重複的縣市名。例如 `新竹市新竹市東區…` 正規化為 `新竹市東區…`。目標 `building_key` 須保留相同規則並由獨立案例驗證。不刪除不同名稱或疑似舊縣市名，也不據此推測行政區。

## 離線候選與定位

1. 候選必須符合門牌簽章。交易地址有寫村里或鄰時，只保留相同子識別的候選。
2. 只有一個相異座標時，可定位。
3. 同一門牌有多個不同座標時，套用 30 m 規則。所有座標兩兩距離不超過 30 m 時，取原候選點中的 medoid，也就是到其他候選的距離總和最小者。不計算座標平均。若多點同分，按經度、再按緯度排序取先者。
4. 候選屬不同門牌且有多個相異座標時，不定位，記 `conflict`，列入人工交叉比對。30 m 規則不跨不同門牌套用。
5. 候選涉及不同門牌但全部座標完全相同時，可採用該共同座標。保留各門牌候選及證據，不把不同門牌鍵合併。
6. `address_observations.parquet` 是地址池鍵與候選列的投影。`building_key` 是地址池鍵。`evidence_id` 由原 `evidence_id`、U+001F 與地址池鍵串接後取 SHA-256。原列依 `input_sha256`、`source_ref`、`source_row_number` 回查。狀態報告包含 `door_rule = village_neighborhood_subid_v1` 與 `door_cross_check_keys`。
7. `build-review` 將 `door_cross_check` 寫入獨立的 `cross_check_addresses.parquet` 及 CSV，不併入 `coordinate_conflict`。待查核原因還包含 `annex_variant_pair`、`named_lane_variant_pair`、`lane_numeral_variant_pair`、`bracket_note`。

地址基底的來源優先序只在完整同址已確認後套用。TGOS 是已確認同址後的最高優先來源；同級來源的座標相衝時保留衝突，不任選或平均。完整同址失敗時，來源優先序不能使候選變成可採用。

## 缺區地址的離線補區（R05-7）

補區在 `build-address-pool` 提供 `--index` 時執行。補區不改交易原文，使用 `district_fill_rule = road_unique_v1`、`repeated_county_rule = exact_repeat_v1` 綁定。補區後仍須重新依完整門牌規則定位，既有地址鍵與既有定位不因新增一筆補區成員而改變。

1. 完全重複的縣市名依 `identity.drop_repeated_county` 移除。
2. 有縣市但無法辨識區時，以街路（含段）或地名、巷弄、號，以及地址內已有的村里和鄰查詢固定離線索引中的該縣市。
3. 沒有縣市與區、但有路名時，以來源 ZIP 成員檔名的縣市字母限制查詢範圍。來源縣市未知時才查全台。
4. 候選只屬於一個區時補入該區。有縣市時原因為 `road_unique_in_county`，只有路名時為 `road_only_unique`。地址池成員保存補區文字及鍵，原始交易地址不修改。
5. 候選分屬兩個以上的區時不補，即使座標完全相同也不選區。有縣市時原因為 `district_ambiguous`，只有路名時為 `road_only_not_unique`。候選有多個相異座標時另列人工交叉比對。
6. 無候選時，有縣市記 `district_missing`，供符合條件的 R09-6 TGOS 送查；只有路名記 `road_only_not_unique`。縣市後文字像行政區名但解析失敗時記 `invalid_admin`，例如 `市東區…`、`v新興區…` 或舊縣名 `桃園縣…`。
7. 每次查詢寫入 `district_candidates.parquet`，包含查詢範圍、來源縣市、候選區數、相異座標數及候選門牌。離線狀態使用同一證據產生 `district_missing`、`district_ambiguous` 與 `road_only_not_unique` 查核列。
8. 地址池代表地址優先取未補區成員。新增補區成員不改變既有鍵的代表地址與既有定位結果。

## 座標有效性

座標參考系為 WGS84。`X` 是經度，`Y` 是緯度。不得依數值大小猜測或交換座標軸，軸向不明時不採用定位。

有效範圍包含邊界：經度 `118` 至 `123.5`，緯度 `21.5` 至 `26.5`。範圍外記 `invalid_coordinate` 並保留來源座標原值，不替換或裁切。

澎湖縣 `10016` 與金門縣 `09020` 依擁有者決定暫停所有來源定位。這些地址鍵記為 `conflict`，原因 `address_source_suspended`，不是 `outside_scope`。即使既有 TGOS 證據曾標為 `located`，暫停期間也不可採用；待來源修正或暫停清單更新後重建定位。不可換算約偏東的來源座標，也不選為新 TGOS 候選。連江縣不在暫停清單。

## TGOS 回傳與同址

採用 TGOS 座標前核對回傳集合與送出查詢一對一、行政區、街路、段、巷、弄、主號、子號及座標。回傳可補上送出地址未寫的村里或鄰，但無村里地址在基底中跨多村里或鄰時不得逕自採用。這個跨村里候選核對由 R09-2 補足，尚未完成驗收。

查詢和回傳缺列、重複列、混入其他批次、地址不完整、門牌不符、座標軸不明或超出範圍時，保留原因並拒絕或隔離。相同批次與回傳雜湊具備冪等重匯處理。`submission_unknown` 不自動重送，也不釋放配額。

## 地址補充交接

交接 CSV 使用以下 14 欄，欄名大小寫及順序固定：

```text
FULL_ADDR,COUNTY,TOWN,VILLAGE,NEIGHBORHOOD,ROAD,SECTION,LANE,ALLEY,SUB_ALLEY,TONG,NUMBER,X,Y
```

`X` 為經度，`Y` 為緯度。內部 Parquet 欄名與 CSV 大寫欄名由匯出端轉換。缺少行政代碼時不得編造。交接另保留來源關聯、採用依據及隔離原因。

| 結果 | 分類與後續 |
| --- | --- |
| 地址基底中不存在且證據有效 | 新增候選 |
| 地址已存在且座標相同 | 既有地址補充證據，不重複新增 |
| 地址已存在但有效座標需更新 | 更新候選，保留前後值及依據 |
| 地址不符、代碼缺失或多解、座標無效或衝突 | 隔離，保留原因 |

候選產生不等於地址專案已匯入。真實匯入前須完成全基底重複稽核，跨專案結果獨立記錄。
