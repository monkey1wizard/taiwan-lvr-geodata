# 輸出欄位

修訂日期：2026-10-11，Asia/Taipei。狀態：草案，待擁有者確認。用詞定義見[名詞定義](glossary.md)，輸出規格見[重建企劃 6.5](plans/重建企劃.md)。

輸出只收錄有座標的門牌，一個門牌一列。一筆交易有多個門牌時，會有多列，這些列的交易欄位相同。

## 待擁有者決定

1. 欄位名稱：採用下表的「建議名稱」，或維持「程式現名」只在文件解釋。
2. `door_key` 與 `location_source` 兩欄是規劃者建議新增，是否保留。不保留時共 36 欄。

## 欄位

型別：`string` 文字、`int64` 整數、`double` 小數、`bool` 是非、`geometry` 幾何。「每列不同」表示同一筆交易的各門牌列值不同，其餘欄位在同一筆交易的各列相同。

## 各格式的差異

| 格式 | 位置欄位 | 其他 |
| --- | --- | --- |
| GeoParquet | `geometry` 為 WKB Point，另有 `longitude`、`latitude` | 全部資料一個檔，依交易年月與類別排序 |
| GeoPackage | `geometry` 為圖層幾何欄，另有 `longitude`、`latitude` | 每年一檔，三類各一個圖層，圖層名稱為類別 |
| CSV | 只有 `longitude`、`latitude`，沒有 `geometry` 欄 | UTF-8，是否加 BOM 待實測 Excel 後決定 |
| GeoJSON | 幾何放在 Feature 的 `geometry`，其餘欄位放在 `properties` | Feature 的 `id` 為門牌識別碼 |

## 加總金額的規則

同一筆交易的多個門牌列，`total_price` 與 `amount_minor` 相同。統計金額時：

- 只加總 `price_counted = 1` 的列，或
- 依 `transaction_id` 去重後再加總。

統計交易筆數時，同樣只計 `price_counted = 1` 的列。

## 與原始資料的對照

原始資料是內政部實價登錄每批 ZIP 內的 CSV。每個縣市一組檔案，檔名第一個字母是縣市，`_a` 為買賣、`_b` 為預售屋、`_c` 為租賃，例如 `a_lvr_land_a.csv` 是臺北市買賣。以下欄位名稱取自 115q1 批次，較舊批次的欄位名稱可能不同，程式以別名處理。

### 輸出欄位的來源

### 只在 `props_json` 裡的原始欄位

以下原始欄位沒有獨立的輸出欄位，完整保留在 `props_json`。

| 類別 | 欄位 |
| --- | --- |
| 三類共有 | `交易標的`、`都市土地使用分區`、`非都市土地使用分區`、`非都市土地使用編定`、`總樓層數`、`主要用途`、`主要建材`、`建築完成年月`、`建物現況格局-房`、`建物現況格局-廳`、`建物現況格局-衛`、`建物現況格局-隔間`、`有無管理組織`、`車位類別`、`備註` |

| 買賣 | `主建物面積`、`附屬建物面積`、`陽台面積`、`電梯`、`移轉編號` |
| 預售 | `建案名稱`、`棟及號`、`解約情形` |
| 租賃 | `土地面積平方公尺`、`租賃筆棟數`、`租賃層次`、`有無附傢俱`、`車位面積平方公尺`、`車位總額元`、`出租型態`、`有無管理員`、`租賃期間`、`有無電梯`、`附屬設備`、`租賃住宅服務` |

### 對照時發現的不一致

1. `total_price` 與 `amount_minor` 的來源不同。預售缺 `總價元` 時，`amount_minor` 改用 `房地總價元`，`total_price` 則為空。租賃缺 `總額元` 時，`amount_minor` 改用 `月租金`，`total_price` 則為空。月租金與總額的意義不同。是否統一，待擁有者決定。
2. `building_area_sqm` 與 `area_m2_decimal` 的來源也不同。租賃缺 `建物總面積平方公尺` 時，`area_m2_decimal` 改用 `建物移轉總面積平方公尺`，`building_area_sqm` 則為空。
3. `county` 由檔名判斷，`district` 取自 `鄉鎮市區` 欄，兩者都是交易層的值。一筆交易的多個門牌如果分屬不同行政區，每一列仍顯示同一個縣市與行政區。
