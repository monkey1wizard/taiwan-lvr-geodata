# 輸出欄位

修訂日期：2026-10-12，Asia/Taipei。狀態：新版公開欄位、格式及目錄是已決定規格，尚未實作或驗收。本文件是唯一新版公開輸出契約。`data/output/` 是已決定的公開 Git 位置，但目前 `.gitignore` 仍忽略整個 `data/`。輸出流程實作、來源映射驗證及待補契約見[重建企劃](plans/重建企劃.md)。用詞見[名詞表](glossary.md)。

## 原則

- 輸出只有門牌圖層。一個有座標的門牌一列，幾何為 Point。不提供交易圖層。
- 照實呈現交易。原始資料只有一個總價時，就只呈現一個總價，不分攤到各門牌，也不推算各門牌的價格。
- 一筆交易有多個門牌時，每一列都要讓人看出這是多門牌交易，也看得出這筆交易合併了什麼。
- 有含車位時，車位的數量、類別、價格、面積都照原始值呈現。
- 只收錄有座標的門牌。沒有座標的門牌等 TGOS，不放進輸出。
- `address` 與 `transaction_addresses` 都直接填本次新重建來源的地址欄原文。TGOS 更新 `address` 的前提是依新規則核驗該回傳，並明確納入本次新基線。
- 本次新基線中經新規則核驗並納入的 TGOS 或人工查核結果，可更新覆蓋地址與座標結果。不得自動讀取重建前的 TGOS 採用結果、review 裁定或舊快照。座標由誰決定不放進輸出，記在執行目錄，見「記在執行目錄，不放進輸出」。
- 每列都相同的值不放進資料表，改記在 `catalog.json`。
- 不使用 decimal 型別，因為 GeoPackage 不支援。原始資料的金額全為整數，存成 int64。面積帶小數，存成 double。
- `props_json` 保留，內含主檔該列的全部原始欄位。
- 35 個欄位及下方檔案映射是已決定的欄位範圍，不代表程式目前已能產生。現有 `output/` 仍使用舊格式及欄位契約。

## 一筆交易多個門牌時

例：原始地址欄 `臺北市萬華區中華路二段３８、３８之１、３８之２、３８之３號`，總價 3,250,000 元，4 個門牌都有座標。輸出有 4 列：

| 欄位 | 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- | --- |
| `transaction_id` | 同一個值 | 同一個值 | 同一個值 | 同一個值 |
| `multi_door` | true | true | true | true |
| `door_index` / `door_count` | 1 / 4 | 2 / 4 | 3 / 4 | 4 / 4 |
| `door_count_located` | 4 | 4 | 4 | 4 |
| `address` | 地址欄原文 | 地址欄原文 | 地址欄原文 | 地址欄原文 |
| `transaction_addresses` | 地址欄原文 | 地址欄原文 | 地址欄原文 | 地址欄原文 |
| `price_twd` | 3,250,000 | 3,250,000 | 3,250,000 | 3,250,000 |
| `price_counted` | 1 | 0 | 0 | 0 |

4 個門牌都由離線定位取得座標時，`address` 都是地址欄原文。其中某個門牌經 TGOS 更新後，該列的 `address` 改為 TGOS 的結果。

使用者從任何一列可以知道：

- 這是多門牌交易：`multi_door` 為 true，`door_count` 大於 1。
- 合併了哪些門牌：`transaction_addresses` 是地址欄原文。
- 合併了哪些標的：`transaction_target`、`land_count`、`building_count`、`parking_count`，以及車位欄位。
- 總價屬於整筆交易，不是這一個門牌：`price_twd` 在各列相同，加總時只計 `price_counted` 為 1 的列。
- 同一筆交易的其他點：以 `transaction_id` 篩選。
- 還有幾個門牌在等 TGOS：`door_count` 減 `door_count_located`。

## 待補實作契約

以下工作已有輸出需求及識別輸入，精確的序列化、雜湊與穩定行為尚未定義。補齊契約前不得自行推斷。

- `transaction_id` 使用來源 ZIP SHA-256、ZIP 內成員路徑及來源實體列號三項輸入，不把不同來源列推斷成同一交易。精確序列化／雜湊算法及來源修訂後的穩定性待補。
- `door_id` 使用 `transaction_id` 與輸出 `door_index` 作輸入。精確序列化／雜湊算法及門牌拆解規則變更時的穩定性待補。
- 主檔與 `_build.csv`、`_land.csv`、`_park.csv` 之間的明細關聯鍵、缺列／重複列／未匹配處理及跨批來源行為。
- CSV 編碼是否加 BOM，須待指定試算表相容性驗證。
- 未來新版公開契約版本之間的命名、遞增及向後相容策略。不得以此策略接納重建前格式、舊公開輸出或舊衍生結果作為新 run 輸入。

## 欄位

同一筆交易的各列，除了門牌欄位與 `price_counted`，其他值都相同。

### 識別與門牌

| # | 欄位 | 型別 | 說明 |
| --- | --- | --- | --- |
| 1 | `door_id` | string | 門牌識別碼，主鍵，每列唯一。由 `transaction_id` 與 `door_index` 計算 |
| 2 | `transaction_id` | string | 交易識別碼，由來源 ZIP SHA-256、ZIP 內成員路徑及實體列號計算 |
| 3 | `door_index` | int64 | 這是該來源觀測拆出的第幾個門牌，從 1 起算。作為 `door_id` 的識別輸入 |
| 4 | `door_count` | int64 | 地址欄共拆出幾個門牌 |
| 5 | `door_count_located` | int64 | 該交易有座標並在輸出中的門牌數 |
| 6 | `multi_door` | boolean | `door_count` 大於 1 時為 true |
| 7 | `address` | string | 地址欄原文。TGOS 有更新時改為 TGOS 的結果 |
| 8 | `transaction_addresses` | string | 地址欄原文，可能含多個門牌與樓層 |

### 交易內容

| # | 欄位 | 型別 | 說明 |
| --- | --- | --- | --- |
| 9 | `category` | string | `sales` 買賣、`presale` 預售屋、`rent` 租賃 |
| 10 | `trade_date` | string | 交易日期，西元 YYYY-MM-DD |
| 11 | `county` | string | 縣市 |
| 12 | `district` | string | 鄉鎮市區 |
| 13 | `transaction_target` | string | 交易標的原文，例如 `房地(土地+建物)+車位` |
| 14 | `building_type` | string | 建物型態 |
| 15 | `land_count` | int64 | 交易筆棟數中的土地數 |
| 16 | `building_count` | int64 | 交易筆棟數中的建物數 |
| 17 | `parking_count` | int64 | 交易筆棟數中的車位數 |

### 金額與面積

| # | 欄位 | 型別 | 說明 |
| --- | --- | --- | --- |
| 18 | `price_twd` | int64 | 整筆交易的總價，元。租賃為總額。含土地、建物、車位 |
| 19 | `price_counted` | int64 | 加總金額時只計值為 1 的列。每筆交易只有一列為 1 |
| 20 | `unit_price_sqm` | int64 | 每平方公尺單價，元，原始值。原始資料可能為空 |
| 21 | `area_m2_decimal` | double | 建物面積，平方公尺。買賣、預售為建物移轉總面積，租賃為建物總面積 |
| 22 | `parking_type` | string | 車位類別原文。沒有車位時為空 |
| 23 | `parking_price_twd` | int64 | 車位總價，元，原始值。0 表示原始資料未分開計價 |
| 24 | `parking_area_m2` | double | 車位面積，平方公尺，原始值 |

### 來源追溯

| # | 欄位 | 型別 | 說明 |

一筆交易可能有多列明細。三欄都是 JSON 陣列，一個元素是明細檔的一列，鍵名為原始欄位名。沒有明細時為空陣列 `[]`。多門牌交易的各列存同一份明細。

| # | 欄位 | 型別 | 說明 |

## 公開目錄、公告與維護資料

新版目標目錄固定為 `data/output/`。目錄表及檔案分工如下，這是已決定目標，尚未由程式實作：

```text
data/output/
├── NOTICE.json
├── catalog.json
├── gpkg/taiwanlvr_YYYY.gpkg
├── csv/YYYY/taiwanlvr_YYYY_<類別>.csv
├── csv/YYYY/taiwanlvr_YYYYMM_<類別>.csv
└── geojson/YYYY/taiwanlvr_YYYYMM_<類別>.geojson
```

GeoParquet 為完整資料單檔 `taiwanlvr.parquet`，依交易日期及類別排序，放在 GitHub release，不放入 `data/output/` Git 目錄。GeoPackage 每年一檔，含買賣、預售屋、租賃三圖層；CSV 有每年及每月、每類別檔案；GeoJSON 每月、每類別一檔。目錄及檔名中的月份使用兩位數。

`catalog.json` 是此公開目錄的檔案索引。每個資料檔案須列出格式、適用的年、月與類別、期間粒度、筆數、檔案大小、SHA-256 及檔案位置。期間粒度區分全歷史、整年及單月，檔案位置區分公開目錄的相對路徑與 GeoParquet 的 release 位置。幣別固定為 `TWD`。欄位版本與截止年月等本次輸出共通資訊記於 catalog，不重複放進每列。JSON 的具體序列化與欄位版本命名仍待實作契約補足。

`config/sources/notice.json` 是正式公告的唯一來源，產出時複製為 `data/output/NOTICE.json`，取代舊版公告。公告中的實際來源範圍、來源顯名與限制尚待確認，不從其他公告或本文件推定。

維護資料只存在本機 `data/runs/<run-id>/maintenance/`，不得放進公開目錄或 release。只有本次全新重建且通過 V-10b 的基線所產生、可追溯綁定該基線的維護包，才可供 R08-2a 無原始 ZIP 重產候選及後續私有維護；重建前維護包與舊衍生產物一律禁止。維護包本身不代表候選已通過公開驗證。TGOS 狀態目標位置為 `data/runs/<run-id>/tgos-state/`；第二類人工查核區在 `data/runs/<run-id>/review/`，與待查核表及交叉比對清單分開。以上皆為已決定目標布局，現行命令／預設路徑及 `data/` ignore 尚待實作調整。

- GeoParquet 依交易日期與類別排序。
- GeoJSON 的 Feature `id` 為 `door_id`。
- CSV 為 UTF-8，是否加 BOM 待實測 Excel 後決定。
- GeoPackage 內嵌 QGIS 預設樣式（2026-10-12 擁有者決定）：多門牌交易的點以不同符號顯示，點旁標示 `door_index/door_count`。QGIS 開啟圖層時自動套用。
- CSV 與 GeoJSON 不能內嵌樣式。依 `multi_door` 著色、依 `transaction_id` 篩選同一筆交易的方法，寫在 README。

## 加總金額的規則

只加總 `price_counted = 1` 的列，或依 `transaction_id` 去重後再加總。直接加總全部列，多門牌交易的金額會重複計入。

## 單價的觀察

歷史觀察：依舊版 115q1 臺北市資料比對，車位有另外計價時，多數單價符合「(總價 − 車位總價) ÷ (建物面積 − 車位面積)」。車位沒有另外計價時，多數符合「總價 ÷ 建物面積」。這是當時的比對結果，不是內政部的官方說明，也不是本次新重建驗收證據。輸出照原始單價呈現，不重算。

## 與原始資料的對照

原始資料是內政部實價登錄每批 ZIP 內的 CSV。檔名第一個字母是縣市，`_a` 為買賣、`_b` 為預售屋、`_c` 為租賃，例如 `a_lvr_land_a.csv` 是臺北市買賣。

本節保存舊版 `data/raw/` 標題列盤點的來源映射。當時盤點清單列有 58 批，包含買賣 1,221 個、預售 707 個、租賃 1,111 個 CSV；該次記錄這些來源 CSV 均為 UTF-8。這些數字、欄位和編碼是歷史觀察，不是本次來源清冊、完整性或新驗收基準，也不是本次重新讀取結果。未來來源欄位或編碼可能不同。當時記錄的原始欄位共 52 種：買賣 34 種、預售 31 種、租賃 35 種。

### 三、舊版對照觀察（非新驗收事實）

以下內容是舊版 58 批來源盤點及其對照結果。保留原觀察供追查，不代表本次選定來源的涵蓋、欄位或資料正確，也不能替代獨立重核。

1. 程式為預售準備的別名 `交易年月`、`房地總價元`，以及為租賃準備的 `月租金`，在 58 批中都沒有出現。
2. 總價、總額、單價、車位價格在 58 批中全為整數。建物面積全部帶小數，建物移轉總面積最多 18 位、建物總面積最多 15 位小數，多數應為浮點殘留，此為推論。其他面積最多 2 位小數。
3. `車位移轉總面積平方公尺` 在較舊的 473 個買賣 CSV 寫成 `車位移轉總面積(平方公尺)`。兩者只出現在 `props_json`，鍵名依批次不同。
4. `county` 由檔名判斷，`district` 取自 `鄉鎮市區`，兩者都是交易層的值。一筆交易的多個門牌如果分屬不同行政區，每一列仍顯示同一個縣市與行政區。
