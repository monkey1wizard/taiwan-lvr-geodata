# 輸出欄位

修訂日期：2026-10-12，Asia/Taipei。狀態：欄位已依擁有者 2026-10-11～12 的決定調整，部分項目待決。用詞定義見[名詞定義](glossary.md)，輸出規格見[重建企劃 6.5](plans/重建企劃.md)。

## 原則

- 輸出只有門牌圖層。一個有座標的門牌一列，幾何為 Point。不提供交易圖層。
- 照實呈現交易。原始資料只有一個總價時，就只呈現一個總價，不分攤到各門牌，也不推算各門牌的價格。
- 一筆交易有多個門牌時，每一列都要讓人看出這是多門牌交易，也看得出這筆交易合併了什麼。
- 有含車位時，車位的數量、類別、價格、面積都照原始值呈現。
- 只收錄有座標的門牌。沒有座標的門牌等 TGOS，不放進輸出。
- 每個門牌只存一個地址 `address`，採 TGOS 的標準寫法。離線定位也用同一種寫法。
- TGOS 與人工查核的結果直接更新覆蓋 `address` 與座標，以 `location_source` 標注由誰決定。處理過程的資料分開保存在執行目錄，不放進輸出。
- 每列都相同的值不放進資料表，改記在 `catalog.json`。`location_source` 是擁有者指定的標注，不受此限。
- 與金額、面積有關，原本是浮點數的欄位，改用 decimal。原始資料的金額全為整數，面積帶小數。
- `props_json` 保留，內含主檔該列的全部原始欄位。

## 一筆交易多個門牌時

例：原始地址欄 `臺北市萬華區中華路二段３８、３８之１、３８之２、３８之３號`，總價 3,250,000 元，4 個門牌都有座標。輸出有 4 列：

| 欄位 | 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- | --- |
| `transaction_id` | 同一個值 | 同一個值 | 同一個值 | 同一個值 |
| `multi_door` | true | true | true | true |
| `door_index` / `door_count` | 1 / 4 | 2 / 4 | 3 / 4 | 4 / 4 |
| `door_count_located` | 4 | 4 | 4 | 4 |
| `address` | 臺北市萬華區中華路二段38號 | 臺北市萬華區中華路二段38之1號 | 臺北市萬華區中華路二段38之2號 | 臺北市萬華區中華路二段38之3號 |
| `transaction_addresses` | 地址欄原文 | 地址欄原文 | 地址欄原文 | 地址欄原文 |
| `price_twd` | 3,250,000 | 3,250,000 | 3,250,000 | 3,250,000 |
| `price_counted` | 1 | 0 | 0 | 0 |

上表 `address` 的寫法是示意，實際標準寫法待決，見「待擁有者決定」第 2 項。

使用者從任何一列可以知道：

- 這是多門牌交易：`multi_door` 為 true，`door_count` 大於 1。
- 合併了哪些門牌：`transaction_addresses` 是地址欄原文。
- 合併了哪些標的：`transaction_target`、`land_count`、`building_count`、`parking_count`，以及車位欄位。
- 總價屬於整筆交易，不是這一個門牌：`price_twd` 在各列相同，加總時只計 `price_counted` 為 1 的列。
- 同一筆交易的其他點：以 `transaction_id` 篩選。
- 還有幾個門牌在等 TGOS：`door_count` 減 `door_count_located`。

## 待擁有者決定

1. `multi_door` 是否新增。規劃者提案。
2. `address` 的標準寫法，例如是否含村里與鄰。
3. GeoPackage 是否內嵌 QGIS 預設樣式，讓多門牌交易的點自動以不同符號顯示。規劃者提案。
4. 建物、土地、車位明細檔是否納入。見「與原始資料的對照」第四節。每個車位各自的價格與樓層只在車位明細檔。
5. GeoPackage 沒有 decimal 型別。decimal 欄位在 GeoPackage 中要存成文字以保留精確值，或存成浮點數方便計算。

## 欄位

同一筆交易的各列，除了門牌欄位與 `price_counted`，其他值都相同。

### 識別與門牌

| # | 欄位 | 型別 | 說明 |
| --- | --- | --- | --- |
| 1 | `door_id` | string | 門牌識別碼，主鍵，每列唯一。由交易識別碼與門牌序號算出 |
| 2 | `transaction_id` | string | 交易識別碼，由來源 ZIP 雜湊、ZIP 內檔名與列號算出 |
| 3 | `door_index` | int64 | 這是該交易的第幾個門牌，從 1 起算 |
| 4 | `door_count` | int64 | 地址欄共拆出幾個門牌 |
| 5 | `door_count_located` | int64 | 該交易有座標並在輸出中的門牌數 |
| 6 | `multi_door` | boolean | `door_count` 大於 1 時為 true。待決 |
| 7 | `address` | string | 這一個門牌的標準地址，不含樓層。TGOS 或人工查核的結果直接覆蓋 |
| 8 | `transaction_addresses` | string | 地址欄原文，可能含多個門牌與樓層 |

| # | 欄位 | 型別 | 說明 |

| 11 | `county` | string | 縣市 |

| 13 | `transaction_target` | string | 交易標的原文，例如 `房地(土地+建物)+車位` |
| 14 | `building_type` | string | 建物型態 |

| 17 | `parking_count` | int64 | 交易筆棟數中的車位數 |

## 各格式的檔案

| 格式 | 檔案 |
| --- | --- |
| GeoParquet | `taiwanlvr.parquet`，含全部資料，GitHub release |
| GeoPackage | `gpkg/taiwanlvr_YYYY.gpkg`，每年一檔，三類各一個圖層 |
| GeoJSON | `geojson/YYYY/taiwanlvr_YYYYMM_<類別>.geojson` |
| CSV | `csv/YYYY/taiwanlvr_YYYY_<類別>.csv` 與 `taiwanlvr_YYYYMM_<類別>.csv` |

- GeoParquet 依交易日期與類別排序，decimal 以 Parquet decimal 型別儲存。
- GeoJSON 的 Feature `id` 為 `door_id`。
- CSV 為 UTF-8，是否加 BOM 待實測 Excel 後決定。decimal 照原文位數寫出。
- CSV 與 GeoJSON 不能內嵌樣式。依 `multi_door` 著色、依 `transaction_id` 篩選同一筆交易的方法，寫在 README。

## 加總金額的規則

只加總 `price_counted = 1` 的列，或依 `transaction_id` 去重後再加總。直接加總全部列，多門牌交易的金額會重複計入。

## 單價的觀察

依 115q1 臺北市資料驗算，車位有另外計價時，多數單價符合「(總價 − 車位總價) ÷ (建物面積 − 車位面積)」。車位沒有另外計價時，多數符合「總價 ÷ 建物面積」。這是比對結果，不是內政部的官方說明。輸出照原始單價呈現，不重算。

## 與原始資料的對照

原始資料是內政部實價登錄每批 ZIP 內的 CSV。檔名第一個字母是縣市，`_a` 為買賣、`_b` 為預售屋、`_c` 為租賃，例如 `a_lvr_land_a.csv` 是臺北市買賣。

本節依 `data/raw/` 全部 58 批的標題列整理，共讀取買賣 1,221 個、預售 707 個、租賃 1,111 個 CSV，全部為 UTF-8。原始欄位共 52 種：買賣 34 種、預售 31 種、租賃 35 種。

### 三、對照時確認的事實

1. 程式為預售準備的別名 `交易年月`、`房地總價元`，以及為租賃準備的 `月租金`，在 58 批中都沒有出現。
2. 總價、總額、單價、車位價格在 58 批中全為整數。建物面積全部帶小數，建物移轉總面積最多 18 位、建物總面積最多 15 位小數，多數應為浮點殘留，此為推論。其他面積最多 2 位小數。
3. `車位移轉總面積平方公尺` 在較舊的 473 個買賣 CSV 寫成 `車位移轉總面積(平方公尺)`。兩者只出現在 `props_json`，鍵名依批次不同。
4. `county` 由檔名判斷，`district` 取自 `鄉鎮市區`，兩者都是交易層的值。一筆交易的多個門牌如果分屬不同行政區，每一列仍顯示同一個縣市與行政區。
