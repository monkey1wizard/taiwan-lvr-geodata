# 輸出欄位

修訂日期：2026-10-11，Asia/Taipei。狀態：草案，待擁有者確認。用詞定義見[名詞定義](glossary.md)，輸出規格見[重建企劃 6.5](plans/重建企劃.md)。

輸出只收錄有座標的門牌，一個門牌一列。一筆交易有多個門牌時，會有多列，這些列的交易欄位相同。

## 待擁有者決定

1. 欄位名稱：採用下表的「建議名稱」，或維持「程式現名」只在文件解釋。
2. `door_key` 與 `location_source` 兩欄是規劃者建議新增，是否保留。不保留時共 36 欄。

## 欄位

型別：`string` 文字、`int64` 整數、`double` 小數、`bool` 是非、`geometry` 幾何。「每列不同」表示同一筆交易的各門牌列值不同，其餘欄位在同一筆交易的各列相同。

## 各格式的差異

| 格式 | 位置欄位 | 其他 |
| --- | --- | --- |
| GeoParquet | `geometry` 為 WKB Point，另有 `longitude`、`latitude` | 全部資料一個檔，依交易年月與類別排序 |
| GeoPackage | `geometry` 為圖層幾何欄，另有 `longitude`、`latitude` | 每年一檔，三類各一個圖層，圖層名稱為類別 |
| CSV | 只有 `longitude`、`latitude`，沒有 `geometry` 欄 | UTF-8，是否加 BOM 待實測 Excel 後決定 |
| GeoJSON | 幾何放在 Feature 的 `geometry`，其餘欄位放在 `properties` | Feature 的 `id` 為門牌識別碼 |

## 加總金額的規則

同一筆交易的多個門牌列，`total_price` 與 `amount_minor` 相同。統計金額時：

- 只加總 `price_counted = 1` 的列，或
- 依 `transaction_id` 去重後再加總。

統計交易筆數時，同樣只計 `price_counted = 1` 的列。

### 三、對照時確認的事實

1. 程式為預售準備的別名 `交易年月`、`房地總價元`，以及為租賃準備的 `月租金`，在 58 批中都沒有出現。所以 `total_price` 與 `amount_minor`、`building_area_sqm` 與 `area_m2_decimal` 在實際資料上取自同一個原始欄位。
2. `車位移轉總面積平方公尺` 在較舊的 473 個買賣 CSV 寫成 `車位移轉總面積(平方公尺)`。兩者只出現在 `props_json`，鍵名依批次不同。
3. `county` 由檔名判斷，`district` 取自 `鄉鎮市區`，兩者都是交易層的值。一筆交易的多個門牌如果分屬不同行政區，每一列仍顯示同一個縣市與行政區。是否改為依門牌填寫，待擁有者決定。
