# 資料處理流程

本文件描述目前程式可執行的階段，以及每階段的輸入、處理、輸出和失敗去向。全量流程入口是 `run-full`。它不執行 TGOS。輸出階段已改用新版 22 欄公開契約，但尚未以真實資料執行與驗收。新版階段工作的依賴與驗收見[重建企劃](plans/重建企劃.md)。

2026-10-12 新重建要求：所有既有衍生結果均隔離，不作新流程輸入、定位依據或驗收基準。包含 normalized／converted、地址池／index／state、aliases、TGOS 採用結果、review 裁定、衍生 cache、run／stage 快照、維護包、公開輸出及統計。原始來源清單、ZIP 與地址來源也不能因既存而視為正確或自動沿用，須重新核對。舊 TGOS 回傳結果已於 2026-10-13 由擁有者決定廢棄，不重核、不納入任何新結果；本機已無這些檔案。隔離護欄已於 2026-10-12 實作（R07-6a）：沒有 `rebuild_epoch = 2026-10-12` 的快照與 run 一律拒絕讀入，規則版本不符的快照也拒絕；`run-full` 只接受帶本次紀元的來源清冊與地址來源描述；2026-10-13 決定取消人工簽核，R07-6c 已移除 `source_check` 檢查，清冊改記 `scanned_at`。舊 TGOS 帳本與舊回傳在本機已不存在，不轉接、不擋重送；新重建以新帳本從零開始，離線定位不到的門牌全部重新送查。

下列表格同時列出目前階段事實及待實作的重建要求。R07-6a 隔離護欄與 R07-6b 名稱遷移已實作。來源重掃描（R07-6c）與 R07-6b 規則重驗尚未完成，不得視為已具備的能力。

## 全量離線流程

```text
來源描述與原始 ZIP
  → 核對來源及執行綁定
  → 建立離線地址索引
  → 讀取並正規化交易主檔
  → 建立來源觀測和地址成員
  → 建立地址池與門牌鍵
  → 產生離線定位狀態
  → 建立待查核與交叉比對資料
  → 舊契約輸出階段
  → run report
```

新流程的階段產物只放在本次新 run 的執行目錄。快照重用限於本次重建中已按新規則驗證且輸入綁定一致的階段。不得從重建前的舊 run、衍生 cache、維護包或公開輸出續跑。只有本次新 run 驗收後產生的私有維護包，才可供 R08-2a 在乾淨環境重產候選；R10 只接本次新流程已驗收基線。R07-6a 護欄以 `rebuild_epoch` 阻止跨紀元續跑；舊 TGOS 帳本已不存在，不轉接。每個快照只在建立時逐列驗證一次，下游載入與續跑只核對雜湊，完整重驗用 `verify-snapshot`，見[資料契約](資料契約.md)「快照、版本及續跑」。

## 階段輸入與去向

| 階段 | 輸入與處理 | 產物 | 失敗或等待去向 |
| --- | --- | --- | --- |
| 新輸入重核（R07-6a 護欄已實作，R07-6c 重掃描待做） | 獨立重建來源清單，重新核對來源原文、批次涵蓋、ZIP 成員及地址來源版本；`verify-sources` 的機械檢查不能自證完整或正確 | 新 run 的輸入清冊與來源版本綁定 | 來源或原文無法核實時停止並記錄原因，不用舊盤點或舊結果自證，不把缺檔視為空批次 |
| 離線索引 | 固定地址來源及來源描述。稽核地址列和座標，建立可查詢索引 | 索引、來源證據及稽核結果 | 基底不能完整讀取或契約驗證失敗時，不以部分索引完成後續定位 |
| 讀取與正規化 | 逐批讀取 sales、presale、rent 主檔，驗證日期及欄位，套用規則 | 保留觀測、排除列、解析失敗列及其去向 | 每列保留、排除或失敗。解析失敗會保留診斷。來源涵蓋等式不成立時停止 |
| 地址池（R07-6b 名稱遷移完成，規則重驗待做） | 對保留觀測中的地址文字套用補字及解析規則。程式只用 `building_key`，舊演算法已移除 | 本次觀測與成員關聯、地址池、無法建立鍵的診斷 | 缺字、地址區間、多解或身分不完整時保留原文並列待查核，不猜測或丟棄觀測；移除舊函式、匯出、呼叫及 `legacy_building_key` 欄位讀寫和依賴，不留 alias、wrapper、雙軌或 fallback；以獨立案例驗證規則，不沿用舊預期 |
| 離線定位 | 以地址鍵查固定離線索引，依同址及座標規則核對候選 | 定位狀態、證據與衝突原因 | 無候選、來源暫停、候選跨門牌或座標衝突時保留狀態，不任取座標 |
| Review | 依地址成員與定位狀態建立待查核表及人工交叉比對清單 | `exception_addresses`、`cross_check_addresses` 等查核資料 | 問題留在清單和執行目錄，不能靜默排除。第二類人工查核區依新版契約另行實作 |
| 新版輸出 | `output/build.py` 由 converted 與定位狀態產生逐門牌資料列，寫出 GeoParquet、GeoPackage、CSV、GeoJSON | run 目錄 `output/<output_id>/public/` 與 `release/`，以及記錄每個檔案雜湊的 `output.json` | 寫完後產生 `catalog.json` 並做格式間驗證。驗證失敗時寫 `verify_report.json` 且不提交該階段；目錄已存在且非已驗證的重用時拒絕寫入。全量驗收待 V-10b |
| Run report | 彙整各階段狀態及輸出摘要 | 執行狀態報告 | 必要階段未通過時不應宣告全量完成。已完成的舊契約執行報告不能代替新版驗收 |

明細讀入與關聯已於 2026-10-12 實作（R07-7）：`ingest` 讀入三種明細為 `ingest-detail`，`normalize` 依明細關聯契約以 `編號` 連回主檔，產生 `detail` 資料集，並把七項計數寫入 `detail_link`。三個 JSON 欄由 R07-8 的輸出模組產生。來源觀測以原始列為單位，地址成員以拆出的門牌為單位，定位則以地址鍵為單位。三者的關聯與限制見[資料契約](資料契約.md)。

## TGOS 人工交換

TGOS 使用獨立命令和工作目錄，沒有接入 `run-full`。一輪交換的資料路徑如下：

```text
本次新 run 的離線狀態，加上本次新建的送查帳本
  → prepare-tgos 選候選並寫交換檔
  → 人工上傳及下載回傳
  → set-tgos-status 記錄送出結果
  → import-tgos 核對回傳集合、地址及座標
  → 建立新定位狀態與 review
  → 新版回補待 R-10 實作
```

準備或匯入前須先檢查實際命令的 `--help`。交換檔、原始回傳、狀態及送出紀錄都須保留於工作目錄。沒有取得回傳時，批次留在等待狀態，不自動重送；提交狀態不明時不釋放配額。

`import-tgos` 目前執行查詢與回傳集合一對一檢查、相同批次及回傳雜湊的冪等重匯處理，以及 `same_door` 地址判斷。回傳可補上送出地址未寫的村里或鄰。完整跨村里候選歧義核對仍待 R09-2。回傳不完整、地址不符、座標無效或無法判定時，保留拒絕或隔離原因，不更新原查詢地址的有效定位。

舊 `backfill-output` 已於 R07-8b 刪除。新版結果版本管理與受影響資料重建待 R-10，新版各格式驗證已由 R07-9 實作。

## 回補、交付及失敗

回補的目標流程是使用已驗證證據重建定位狀態，找出所有適用來源觀測，重產受影響月份及年度檔，再驗證新版 catalog 與各格式一致性。實際新版回補仍待 R-10，地址明細讀取與新輸出仍待 R-07 後續卡片。新證據不得覆寫原始資料或先前快照。

公開候選必須經本機候選驗證，再在乾淨 Linux 環境進行無原始 ZIP 的候選重產核對。發布後還要下載公開檔案並核對雜湊與版本。新版維護包只供本機重產與維護，不公開。三段工作分別列在[企劃](plans/重建企劃.md)。

來源不完整、階段驗證失敗、同址證據衝突及磁碟或儲存錯誤都應保留明確失敗狀態。檢查輸出及需保留的失敗產物放在 `data/tmp/<purpose>/`。不得將失敗當成空資料或未定位狀態，也不更新公開指標。
