# 資料處理流程

修訂日期：2026-10-11，Asia/Taipei。依據程式提交 `5823d03`、企劃 `docs/plans/重建企劃.md`，以及 `data/` 的實際內容撰寫。

本文件描述目前程式實際的處理流程、每一步的資料位置與 R07-4 真實全量的數量。擁有者 2026-10-11 提出、尚未寫入企劃的輸出要求，集中在第七節，與現行流程分開。

## 一、總覽

```text
(start) data/raw/ 58 個原始交易 ZIP
  │
  ▼
[ run-full：一次全量離線作業 ]          data/runs/<run-id>/
  │
  ├─ 1 verify-sources   核對 58 批來源
  ├─ 2 offline-index    稽核地址基底，建立離線索引
  ├─ 3 ingested         讀取 ZIP
  ├─ 4 normalized       每列分成保留、排除、失敗
  ├─ 5 converted        保留觀測與地址成員
  ├─   涵蓋核對          全部批次與每列去向
  ├─ 6 address-pool     地址成員產生地址鍵
  ├─ 7 offline-state    地址鍵查離線索引，決定定位狀態
  ├─ 8 review           待查核表與人工交叉比對清單
  ├─ 9 output           月檔、年度檔、點位檔、維護包
  └─ 10 run-report      完成狀態與摘要
  │
  ▼
(end √) 離線成品，不含 TGOS 結果

[ TGOS 線：另外以個別命令執行，未接進 run-full ]
  │
  ├─ prepare-tgos       從未定位地址選出送查候選
  ├─ 人工上傳與下載      data/tgos/<日期-批次>/
  ├─ import-tgos        驗證回傳，更新定位狀態
  ├─ build-review       以 TGOS 狀態重建待查核表
  ├─ backfill-output    以 TGOS 狀態重建成品
  └─ export-address-patch  產生地址專案的新增與更新候選
```

| 單位 | 意義 | R07-4 數量 |

## 四、run-full 各階段

### 1 verify-sources

- 輸入：`config/sources/raw_manifest.json` 與 `data/raw/`。
- 處理：逐批核對檔案、雜湊、ZIP 成員。已知空批次必須在清單中標明，缺檔不能當作空批次。
- 失敗時：不建立任何階段，`run-full` 結束代碼 1。
- R07-4：58 批全部通過，已知空批次 1 批（101q1）。

### 2 offline-index

- 輸入：`../taiwan-address-data` 提交 `3ff9be02…`，描述檔 `config/sources/address_source.json`。
- 處理：稽核地址基底的重複、無效與座標差異，建立離線索引。座標超出臺灣範圍的列記為 `invalid_coordinate`。

### 3 ingested、4 normalized

- 處理：逐批讀取三類交易 CSV，`sales` 為買賣、`presale` 為預售、`rent` 為租賃。
- 每列有一個去向：

| 去向 | 條件 | R07-4 |
| --- | --- | --- |
| 保留 | 有門牌地址的交易 | 4,377,484 |
| 排除 | 土地 1,344,783、無門牌 372,034、純車位 71,734、日期無效 3,679 | 1,792,230 |
| 失敗 | 無法解析的列，例如欄數錯誤 | 44 |
| 合計 | 輸入列數 | 6,169,758 |

- 交易月份由 `validated_roc_to_tx_yyyymm` 與截止年月 202610 決定。
- 補字規則 `config/rules/character-fixes.csv` 在此套用。原文保留在 `raw_address`，補字後的文字在 `normalized_address`。

### 5 converted

- 產生保留觀測與地址成員。一個地址欄寫多個門牌時，拆成多個成員。
- 涵蓋核對：每一批都必須出現，已知空批次相符，每個 ZIP 成員的「輸入 = 保留 + 排除 + 失敗」都要成立。不成立時停止，不寫完成狀態。

### 6 address-pool

- 每個地址成員依地址規則產生地址鍵。地址規則見 `docs/architecture.md` 的地址處理規則。
- 門牌辨識包含縣市、鄉鎮市區、街路或地名、巷、弄、號、之號。樓層不參與門牌辨識。
- 村里或鄰不同，就是不同門牌。
- 產生不了鍵的成員，例如區名無法辨識、門牌區間、缺字，會記錄狀態並保留原文。
- 缺區的地址，以離線索引查是否只有一個區有這個門牌，有就補區。

### 7 offline-state

每個地址鍵查離線索引，得到以下其中一種狀態：

| 狀態 | 條件 | R07-4 地址鍵數 |
| --- | --- | --- |
| `located` | 找到座標。同一門牌的多個座標兩兩相距 30 m 以內，選中心點 | 1,074,516 |
| `unmatched` | 離線索引沒有這個門牌 | 188,806 |
| `conflict` | 同一門牌的座標相距超過 30 m，或候選分屬不同門牌且座標不同，或位於暫停定位的縣市 | 3,450 |

暫停定位的縣市是澎湖 `10016`、金門 `09020`，原因是地址資料來源的經度偏東約 2 度，清單在 `config/pipeline.example.toml`。

### 8 review

只列出問題，不修改也不移除任何資料。產生兩個檔案：

- `exception_addresses.parquet` 與 `.csv`：待查核表。每列是一個地址成員加一個原因代碼。
- `cross_check_addresses.parquet` 與 `.csv`：人工交叉比對清單。交易沒寫村里或鄰，而候選門牌分屬多個村里或鄰、座標又不同的地址，列在這裡，由擁有者人工查證。

原因代碼共 19 個：

### 9 output

- 輸入：converted 快照、offline-state 快照、公告檔、附件上限。
- 成品位置：`data/runs/<run-id>/output-release/<output_id>/`。`output_id` 由這四項的雜湊算出，任一改變就產生新目錄。
- 每一筆保留觀測都寫入月檔。沒有座標的觀測也寫入，幾何為 null。
- 幾何依該觀測的地址成員決定：

```text
{ 該觀測有座標的成員數? }
  ├── 0 ─────────────▶ geometry null，location_status none
  ├── 全部，只有 1 點 ─▶ Point，location_status complete
  ├── 全部，多點可圍成範圍，非租賃 ─▶ bbox Polygon，is_approximation true
  ├── 全部，其餘多點 ──▶ MultiPoint
  └── 部分 ──────────▶ 只用有座標的成員畫，location_status partial
```

- R07-4 觀測數：complete 3,639,298、partial 489、none 737,697。

成品內容：

| 項目 | 位置與命名 | R07-4 數量 |
| --- | --- | --- |
| 月檔 | `monthly/YYYY/YYYYMM/YYYYMM_<類別>.parquet`、`.geojson`、`.ndjson`，每檔 36 欄 | 1,683 個 |
| 月清單 | `monthly/YYYY/YYYYMM/YYYYMM_manifest.json` | 187 個 |
| 年度包 | `yearly/YYYY/lvr_YYYY_<格式>.zip`，內容是同版月檔原位元組 | 48 個 |
| 年度點位檔 | `yearly/YYYY/YYYY_<類別>_points.csv`，只收完整定位且只有一個點的觀測，12 欄。同一座標的多筆交易錯開不超過 1 m | 48 個，3,637,186 列 |
| 年清單 | `yearly/YYYY/YYYY_manifest.json` | 16 個 |
| 維護包 | `<output_id>_maintenance.part001.zip`、`part002.zip`、`_maintenance_index.json`，內含 converted 與 offline-state 快照，可不用原始 ZIP 重產月檔 | 3 個 |
| 公告 | `NOTICE.json` | 1 |
| 大小報告 | `size_report.json` | 1 |
| 總清單 | `manifest.json`，記錄每個附件的路徑、大小、SHA-256 | 不算附件 |

- 驗證：`verify_output` 核對附件雜湊、三格式逐列一致、GIS 屬性可由來源重算、定位狀態與幾何規則、年度包成員雜湊、點位檔、維護包可解開。不通過就不提交 `output` 階段，也不寫 `run-report`。
- R07-4：1,987 個附件，30,266,819,130 bytes，最大附件 2,033,660,438 bytes。

### 10 run-report

- 只有前面全部通過才寫入，這是整次作業唯一的完成狀態。
- 內容：批次、列去向、地址鍵狀態、待查核原因數、輸出摘要、資源量測。

## 五、TGOS 線

TGOS 線目前以個別命令執行，狀態寫在 `--work-dir` 指定的工作目錄，例如 `data/tmp/work/r09-0/tgos-state/`，不在 `data/runs/`。`run-full` 不讀取 TGOS 狀態。

```text
(start) 離線狀態與既有送查紀錄
  │
  ▼
[ prepare-tgos ]
  │ 候選：unmatched 且有鍵的地址
  │ 排除：已定位、衝突、缺字、暫停縣市、已送出或已保留的查詢
  │ 每批上限 10,000 筆
  ▼
[ 交換檔 ]  data/tgos/<YYYYMMDD-批次>/addresses.csv
  │
  ▼
[ 人工上傳 TGOS addrCompare，人工下載 Address_Finish.csv ]
  │
  ▼
[ set-tgos-status ]  記錄已送出、未送出或取消
  │
  ▼
[ import-tgos ]  逐筆驗證回傳
  ├── 座標有效，且回傳與送出是同一門牌 ──▶ 採用，地址鍵變成 located
  ├── 回傳門牌不同 ────────────────────▶ 隔離，tgos_isolated
  ├── 回傳地址不完整 ──────────────────▶ tgos_response_incomplete
  ├── 座標超出臺灣範圍 ────────────────▶ tgos_coordinate_invalid
  └── 查無結果 ────────────────────────▶ 維持 unmatched
  │
  ▼
[ build-review --tgos-state ]  待查核表改以 TGOS 最終狀態列出
  │
  ▼
[ backfill-output ]  以 TGOS 狀態重建成品，核對沒變的月檔雜湊相同
  │
  ▼
[ export-address-patch ]  已採用的 TGOS 證據產生地址專案 14 欄候選
```

- 同址判定：送出地址沒寫村里或鄰、回傳有寫時，接受回傳補上的村里或鄰。其他部分都必須相同。
- 已知缺口：送出地址沒寫村里，而地址基底中同一門牌跨兩個以上村里時，目前沒有阻擋採用，記在 R09-2。
- R09-0 真實資料：兩批回傳匯入後，由 TGOS 定位的地址鍵 9,988 個。結果在 `data/tmp/work/r09-0/`，沒有進入 R07-4 成品。

## 六、公開發布

- 命令：`publish-output` 建立 GitHub draft release，上傳全部附件並下載核對，再公開。`commit-release-pointer` 更新 `releases/latest.json` 並推送到 `main`。
- 限制：GitHub 每個 release 最多 1,000 個附件，`publish_release` 也有同樣上限。R07-4 成品有 1,987 個附件，目前無法發布。
- 已公開版本：`data-p2-115q1-offline-v2`，只含 115q1 一批，914 個附件。以現行規則無法重產驗證，原因是舊快照沒有記錄規則版本。

## 七、擁有者 2026-10-11 提出、尚未寫入企劃的要求

以下要求與現行實作或企劃文字不同。改動前要先修訂企劃，再開卡實作。

| # | 要求 | 現行實作與企劃 |
| --- | --- | --- |
| 1 | 沒有座標的不進 output，留在未定位池等 TGOS | output 寫入全部觀測，未定位為 null 幾何。企劃 5.1、6.4 與 `architecture.md` 寫明未定位觀測仍須輸出 |
| 2 | TGOS 後仍查不到的，放進第二類人工查核區 | 不存在第二類查核區。TGOS 失敗與離線查不到同列在待查核表，以原因代碼區分 |
| 3 | TGOS 結果回補到 output | `run-full` 不讀 TGOS 狀態。回補只有 `backfill-output` 個別命令 |
| 4 | 一個地址就是一個座標 | output 以觀測為單位。企劃 12.2 已裁定「一個點是一筆交易，一筆交易不拆成多點」，多門牌交易存成多點列在 12.2 待決 |
| 5 | 公開發布只有一個 ZIP，內含單一 GeoParquet | 現行發布是依月、年、格式拆開的 1,987 個附件 |
| 6 | 本機輸出 CSV、GeoJSON、NDJSON，各分 `YYYY/` 整年檔與 `YYYY/MM/` 單月檔，三類分開，每檔 36 欄 | 現行本機成品結構見第四節 9 |
| 7 | 舊成品全部刪除 | `data/output/` 仍有 `fast2-output-e`、`p2-115q1-offline-v2`，`data/runs/r07-4-full/output-release/` 仍在 |

第 4 項與企劃已裁定的原則衝突。一筆交易登記兩個門牌時，output 要一個點還是兩個點，需要擁有者決定。
