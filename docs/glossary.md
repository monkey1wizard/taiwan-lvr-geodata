# 名詞定義

修訂日期：2026-10-11，Asia/Taipei。

本文件統一本專案的用詞。文件、紀錄與討論都以這裡的定義為準。程式中的舊名稱列在第七節，改名前兩者並存。

## 一、資料的單位

以一筆交易為例，原始資料的地址欄寫著 `臺北市大安區測試路10、12號5樓`：

```text
交易：原始資料的一列
└── 地址欄：臺北市大安區測試路10、12號5樓
      │ 拆開，去掉樓層
      ▼
    門牌 1：臺北市大安區測試路10號 ──▶ 門牌鍵 ──▶ 座標
    門牌 2：臺北市大安區測試路12號 ──▶ 門牌鍵 ──▶ 座標
```

| 名詞 | 定義 |
| --- | --- |
| 交易 | 原始資料 CSV 的一列。不推斷兩列是否為同一筆真實交易，也不合併 |
| 地址欄 | 交易原本寫的地址文字。可能寫多個門牌，也可能含樓層 |
| 門牌 | 從地址欄拆出的一個門牌，不含樓層。一個門牌就是一個座標 |
| 門牌鍵 | 門牌的標準化身分。同一門牌的不同寫法、不同樓層，得到同一個門牌鍵。不同交易寫同一門牌時，共用同一個門牌鍵 |
| 座標 | 門牌的經度與緯度，WGS84 |

門牌的辨識規則：縣市、鄉鎮市區、街路或地名、巷、弄、衖、號與之號都相同才是同一門牌。村里或鄰不同就是不同門牌。樓、樓之、室不參與辨識。

## 二、來源

| 名詞 | 定義 |
| --- | --- |
| 批次 | 內政部實價登錄的一個季度下載檔，例如 `115q1`。來源清單共 58 批 |
| 已知空批次 | 來源清單中標明沒有資料的批次，目前是 `101q1`。缺少檔案不能當作空批次 |
| 類別 | `sales` 買賣、`presale` 預售屋、`rent` 租賃 |
| 交易年月 | 由交易日期換算的年月，不是批次的季度。例如 115q1 批次內可能有 2025 年的交易 |
| 地址資料 | 地址資料專案 `taiwan-address-data` 的固定版本，提供門牌與座標 |
| 離線索引 | 由地址資料建立、供查詢門牌座標的索引 |

## 三、每列交易的去向

| 名詞 | 定義 |
| --- | --- |
| 保留 | 有門牌地址、進入後續處理的交易 |
| 排除 | 土地、無門牌、純車位、日期無效等不處理的交易，保留原因 |
| 失敗 | 無法解析的列，例如欄數錯誤，保留原文 |

每一列都有保留、排除、失敗其中一個去向，三者相加等於輸入列數。

## 四、定位

| 名詞 | 定義 |
| --- | --- |
| 定位 | 為門牌找到座標 |
| 已定位 | 門牌有可採用的座標 |
| 未命中 | 離線索引沒有這個門牌 |
| 衝突 | 同一門牌的座標相距超過 30 m，或候選分屬不同門牌且座標不同，或位於暫停定位縣市。不採用任何座標 |
| 30 m 容許值 | 同一門牌的多個座標兩兩相距不超過 30 m 時，視為同一棟的記錄誤差，取中心點 |
| 暫停定位縣市 | 地址資料座標有誤、暫不定位的縣市，目前是澎湖 `10016`、金門 `09020` |
| 未定位池 | 未命中且可送 TGOS 的門牌集合 |
| TGOS | 內政部國土測繪中心的門牌比對服務，以人工上傳與下載交換檔 |
| 送查 | 把未定位池的門牌整理成交換檔，交給 TGOS 比對 |
| 同址 | TGOS 回傳的門牌與送出的門牌是同一門牌。不是同址的回傳不採用 |
| 回補 | TGOS 找到座標後，把該門牌加入輸出 |

## 五、查核清單

| 名詞 | 定義 |
| --- | --- |
| 待查核表 | 離線處理後仍有問題的門牌，每列附一個原因代碼，例如未命中、衝突、缺字。檔名 `exception_addresses` |
| 人工交叉比對清單 | 交易沒寫村里或鄰，而候選門牌分屬多個村里或鄰、座標又不同的門牌，由擁有者人工查證。檔名 `cross_check_addresses` |
| 第二類人工查核區 | 送查 TGOS 後仍找不到座標的門牌。與上面兩份分開。尚未實作 |

## 六、輸出

| 名詞 | 定義 |
| --- | --- |
| 輸出 | 公開給使用者的成品，只收錄有座標的門牌。一個門牌一列，幾何為 Point。同一筆交易的各門牌共用 `transaction_id`，交易欄位在各列重複。不提供交易圖層 |
| 多門牌交易 | 地址欄拆出兩個以上門牌的交易。輸出以 `multi_door`、`door_index`、`door_count` 標示，`transaction_addresses` 保留地址欄原文 |
| `address` | 輸出欄位，一個門牌一個。直接填地址欄原文，TGOS 有更新時改為 TGOS 的結果 |
| 整年檔 | 一年一類別一個檔，例如 `taiwanlvr_2025_sales.csv` |
| 單月檔 | 一個月一類別一個檔，例如 `taiwanlvr_202501_sales.csv` |
| `price_counted` | 加總金額時只計值為 1 的列。一筆交易有多個門牌時，總價在各列重複出現，只有其中一列為 1 |
| `catalog.json` | 輸出全部檔案的目錄，記錄格式、年、月、類別、筆數、大小與雜湊 |
| `NOTICE.json` | 資料來源、授權與限制聲明 |

## 七、程式名稱對照

程式與舊文件中的名稱如下。輸出欄位見[輸出欄位](輸出欄位.md)。

| 本文件用詞 | 程式中的名稱 | 輸出欄位名稱 |
| --- | --- | --- |
| 交易 | 來源觀測 `source_observation`，識別碼 `raw_record_id` | `transaction_id` |
| 地址欄 | `raw_address` | `transaction_addresses` |
| 門牌 | 地址成員 `address_component`，識別碼 `component_id` | `door_id` |
| 門牌的地址 | 交易層的 `address` 為整個地址欄 | `address` |
| 交易的門牌數 | `address_component_count` | `door_count` |
| 交易已有座標的門牌數 | `located_component_count` | `door_count_located` |
| 門牌在交易中的序號 | 無 | `door_index` |
| 門牌鍵 | `building_key`、`building_key_v2` | 不輸出 |
| 已定位、未命中、衝突 | `located`、`unmatched`、`conflict` | 不輸出，輸出只有已定位 |
| 座標來源 | 無 | 不輸出，記在執行目錄的 `tgos-state/` 與 `review/` |

## 八、執行

| 名詞 | 定義 |
| --- | --- |
| 全量作業 | 一次處理全部 58 批的 `run-full`，執行目錄在 `data/runs/<run-id>/` |
| 階段 | 全量作業中的一個步驟，例如 `normalized`、`offline-state`、`review` |
| 快照 | 一個階段完成並驗證後的資料，內容不可修改 |
| 續跑 | 中斷後再執行時，重用已完成且核對相符的階段 |
